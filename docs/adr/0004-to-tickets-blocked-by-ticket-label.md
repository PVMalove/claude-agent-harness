# `to-tickets` получает собственный узкий лейбл `blocked-by-ticket`; снимает его `implement`, не `triage`

> Таксономический контекст этого ADR (canonical roles vs `workflow::*`) обращён в [ADR 0005](0005-triage-workflow-taxonomy-restored.md) — `blocked-by-ticket` стало снова `workflow::blocked`. Решение *этого* ADR о том, кто снимает блокировку (`implement`, не `triage`), осталось в силе.

`triage` вернулся к апстримной канонической паре ролей (`bug`/`enhancement` + 5 состояний) вместо namespaced-таксономии (`hitl`/`afk` + `type::*` + `workflow::*`) — `skills/first-party/pvmalove/triage/` удалён, override убран из `pvmalove-suite`. Это забрало у пайплайна состояние `workflow::blocked`, которым раньше `to-tickets` помечал тикет, заблокированный ещё не закрытым тикетом той же декомпозиции, и переход `workflow::blocked → workflow::ready`, которым это раньше снимал `triage`.

`to-spec` и `to-tickets` сохранили собственную функциональность (epic-issue после `/to-spec`, декомпозиция на связанные подзадачи через `/to-tickets`) — она не зависела от вернувшейся к канону triage-таксономии, только от одного контекстного лейбла `epic::<slug>`, который `triage` никогда не читал. По той же схеме `to-tickets` получил второй контекстный лейбл, `blocked-by-ticket`: узкий, не тянет за собой модель триажа, применяется вместо `ready-for-agent` только к тикетам с открытыми блокерами внутри одной декомпозиции. Снимать его стало обязанностью `implement`, а не `triage`: перед стартом работы над конкретным тикетом (только если в вызове есть явная ссылка на тикет — номер issue, URL или путь `.scratch/.../issues/NN-*.md`) он проверяет блокеры тем же механизмом, что уже использует `wayfinder` (native GitHub/GitLab dependency links, текстовый `Blocked by:` fallback). Если все закрыты — снимает `blocked-by-ticket`, ставит `ready-for-agent`, продолжает работу; если нет — отказывается стартовать и называет открытые блокеры. Для локального markdown-трекера, где нет PR/merge-закрытия, `implement` дополнительно ставит тикету новый терминальный `**Status:** done` по завершении работы — симметрично обязательному `Closes #<ID>` в теле PR для GitHub/GitLab (`docs/agents/git-workflow.md`).

**Rejected**: не хранить лейбл вовсе, а считать блокировку исключительно на лету при каждом запросе (как уже делает `wayfinder` для своих карт) — самый дешёвый вариант, не требует, чтобы что-либо его снимало. Отклонено: декомпозиции `to-tickets`, в отличие от Wayfinder-карт, обычно просматриваются человеком прямо в списке issues на трекере, где лейбл даёт мгновенный визуальный сигнал без похода в UI нативных зависимостей.

**Rejected**: снимать лейбл через повторный вызов/sweep-режим самого `to-tickets`, перепроверяющий все ранее созданные им тикеты. Отклонено в пользу проверки в момент старта работы (`implement`) — не нужен отдельный шаг, который кто-то должен не забыть запустить; проверка происходит ровно тогда, когда она нужна.
