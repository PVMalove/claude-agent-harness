# First-party-переопределения скиллов — полные файлы, а не unified-diff патчи

Переопределение (`overrides`, см. ADR 0001) физически ссылается на скилл в `skills/first-party/pvmalove/<имя>/SKILL.md`. Рассматривались два формата содержимого: unified-diff, применяемый через `git apply` к vendor-версии при разрешении капабилити, или полная копия файла.

Diff даёт наглядный минимальный список изменений, но ломается при малейшем текстовом дрейфе апстрима — придётся вручную перегенерировать патч при каждом `harness update` базовой капабилити, и ошибка применения патча возникает уже во время `init`/`update` пользователя, а не во время авторства. Полная копия никогда не ломается при применении: `harness/bin/harness` просто читает её содержимое как обычный скилл — сравнение с апстримом делается вручную (`diff` между vendor- и first-party-версией), когда нужно понять, что именно изменено.

Выбрана полная копия — цена: явного минимального diff в репозитории нет, при ручном пересмотре изменений нужно сравнивать файлы самостоятельно.
