# qa-gate/pr-composer читают команды и PR-шаблон из .harness/project.json, а не автодетектят и не хардкодят

`qa-gate` и `pr-composer` — first-party-скиллы без апстримного аналога (обобщены из ProductFlow-специфичных версий). Им нужны команды lint/test/typecheck, формат PR-описания, `branch_pattern` и `language` — величины, разные в каждом целевом проекте.

Рассматривались: (1) автодетект по `Makefile`/`package.json`/`pyproject.toml` — хрупко для нестандартных раскладок и требует кода-эвристики внутри скилла; (2) плейсхолдеры в самом `SKILL.md`, правятся вручную после установки — переживает произвольные раскладки, но правку легко забыть, и она теряется при `harness update --force`.

Выбран отдельный файл `.harness/project.json`, который `harness init` заполняет интерактивно при выборе `pvmalove-suite` (см. [[pvmalove-suite]] в CONTEXT.md). Скиллы читают его как обычный проектный файл — переживает обновления харнесса, не требует эвристик, конфиг виден и редактируется напрямую.
