# Оркестрационный workflow передаёт результаты через декларативный версионированный контекст

Runtime передаёт между макро-шагами только явно описанные входы и результаты в versioned workflow context, а `feature-development` заканчивается на `implement`: TDD, code review и qa-gate остаются его внутренним контрактом. Это отделяет маршрутизацию исполнителя от dataflow, делает `context_id`/`spec_file`/`ticket_id` проверяемыми и не допускает дублирования контрольных фаз в графе workflow.
