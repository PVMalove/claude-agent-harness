# Веб-консоль и Сервер консоли

**Статус: ACCEPTED (2026-10-27).** Эпик #862, ADR 0009, ADR 0021, ADR 0025, ADR 0027. Документ
заменяет часть ADR 0009: TUI больше не самодостаточен, потому что получает факты и запускает
команды через Сервер консоли.

## Контекст системы

Принятые макеты консоли свёрстаны в HTML и CSS, а Textual рисует их в сетке символов терминала,
поэтому совпадает с ними только по составу, порядку, подписям и клавишам. Человеку нужна полная
браузерная альтернатива терминальному пульту с живым просмотром шагов агентов и оркестрации.
Эти шаги пока видны разрозненно: наблюдение worker, ledger и отчёты лежат на разных экранах.

ADR 0009 делает TUI самодостаточным: экраны сами собирают факты и запускают команды, а базовая
диагностика работает без сети и без TUI-библиотеки. Это нельзя сохранить вместе с общим живым
состоянием двух клиентов, поэтому контракт ниже заменяет его в части сбора фактов и запуска команд.
ADR 0021 задаёт границу доверия runtime, ADR 0025 — границу контейнерного исполнителя.

## Действующий контракт

### 1. Сервер консоли

На проект запускается один Сервер консоли. TUI и браузер подключаются к нему как клиенты и
говорят на одном протоколе: WebSocket на loopback с токеном. Это единственная поверхность, через
которую клиенты получают снимки фактов, запускают команды и читают события.

- **Запуск и выход.** Первый клиент запускает сервер автоматически. Сервер пишет discovery-файл
  в каталог состояния проекта (права 0600: порт, токен, pid), а следующие клиенты находят его там.
  После grace-периода простоя сервер завершается, если нет подключённых клиентов и активных job.
  При активном job он не завершается.
- **Привязка к проекту.** Сервер обслуживает один проект. Смены проекта из браузера нет: экран
  «Открыть проект» показывает кандидатов и команду для запуска Веб-консоли в другом проекте.
- **Отказ.** Если сервер не стартует (нет `uv`, недоступна зависимость, офлайн без кэша), TUI не
  запускается. Работает прежний fallback ADR 0009: причина, текстовый `harness health`, код
  возврата 1. Команда `harness console --web` ведёт себя так же. Само `harness health` продолжает
  работать без сервера, сети и TUI-библиотеки.
- **Поставка.** Клиенты получают `websockets` и Jinja2 через `uv run --with` по образцу Textual:
  один pin, дубль в dev-группе, тест равенства. Целевой проект свои зависимости не меняет.
- **Запуск `--web`.** Команда печатает URL с токеном, открывает браузер (`--no-open` отключает) и
  завершается. Сервер живёт по правилу простоя.

### 2. Команды и job

Команда каталога запускается на сервере как job. Job имеет id и буфер вывода, принадлежит
серверу, а не клиенту, и переживает отключение клиента. Клиент подключается заново и читает вывод
с нужного смещения. Отмена идущего job — только явное действие с подтверждением.

- **Подтверждения.** Сервер проверяет подтверждение по классу обратимости команды (`Reversibility`)
  так же, как TUI, а не только интерфейс.
- **Конкуренция.** На проект разрешена одна мутирующая команда для всех клиентов, вторая получает
  отказ «занято: <job>». Чтения и live-потоки не блокируются. Вне сервера (CLI, coordinator
  напрямую) действует существующая блокировка ledger.
- **Решения человека.** Dispatch approval, ответ на native permission и терминальные решения
  coordinator выполняются из клиента тем же способом, без второго канала подтверждения.
- **Журнал.** Сервер ведёт локальный append-only журнал команд: время, клиент, argv с
  маскированием секретов, класс обратимости, код возврата. Audit-цепочка Rust и контракт
  coordinator не меняются.

### 3. Живые события

Сервер опрашивает источники по курсору примерно раз в секунду (event log worker, ledger и store
оркестрации) и отправляет клиентам diff по WebSocket. Дорогие проверки (health) выполняются по
запросу или с коротким TTL. Rust runtime не меняется и подписок не получает: он работает по схеме
запрос–ответ (ADR 0021).

Шаги агента ограничены allowlist наблюдения: имена и текст инструментов, без thinking, входов
инструментов и raw JSON. Шаги Claude структурированы. У Codex worker есть только plain-лог, поэтому
клиент показывает его хвост с пометкой «структура недоступна». Структурированный лог Codex —
отдельная задача.

### 4. Безопасность

Сервер слушает только `127.0.0.1` на случайном порту, флага `--host` нет. На handshake проверяются
Host и Origin: WebSocket не защищён политикой same-origin, поэтому одного токена мало. Браузер
получает токен одноразовым URL и дальше хранит его в HttpOnly cookie, TUI берёт токен из
discovery-файла. Страницы отдаются только по GET и HEAD, остальные методы получают 405. Заголовки
строгие, политика содержимого запрещает внешние ресурсы.

### 5. Принятый остаточный риск

Процесс агента работает под тем же пользователем. Неизолированный агент (режим `inherit`) может
прочитать discovery-файл, подключиться к серверу и одобрить свой dispatch. Мы принимаем модель
доверия ADR 0021: файл имеет права 0600, а каталог состояния не монтируется в worker-контейнеры
(ADR 0022). Для `inherit`-worker остаточный риск остаётся, и ADR фиксирует его явно. Второй канал
подтверждения решений человека вне поставки.

### 6. Граница с соседними ADR

- **ADR 0009.** Заменено: самодостаточность TUI (экраны собирают факты и запускают команды сами) и
  допущение, что `uv run --with` нужен только для Textual. Сохранено: Textual остаётся закреплённой
  зависимостью, а fallback «причина + текстовый health, код 1» и независимость `harness health`
  от TUI не меняются.
- **ADR 0027.** Оговорка «консоль остаётся read-only» относится к чтению названий задач на главной
  терминальной консоли и не ограничивает Веб-консоль.
- **ADR 0021 и 0025.** Не меняются. Docker-режим панели вне поставки: контейнерной панели
  потребовался бы доступ к движку и runtime-сокету, а ADR 0021 запрещает монтировать сокет и токен
  runtime в контейнеры, и ADR 0025 запускает worker-контейнеры через движок на хосте. Для такого
  режима нужен отдельный ADR.

## Операционные последствия

- Терминальная консоль теперь зависит от `uv`, `websockets` и процесса сервера. Офлайн-запуск без
  кэша `uv` даёт текстовый health вместо TUI, а неинтерактивная диагностика, агенты и CI не
  зависят от сервера.
- Появляются два новых пина (`websockets`, Jinja2). Обновление любого из них требует проверки
  launcher, fallback и протокола.
- Сервер, discovery-файл и журнал команд создаются в каталоге состояния проекта и в git не
  попадают. На Windows права discovery-файла выставляются через ACL, это проверяет `verify-windows`.
- Протокол проверяется сетевыми тестами на эфемерном порту; браузерный JS и совпадение с макетами
  проверяются ручным чек-листом в PR.
- Новые термины «Веб-консоль» и «Сервер консоли» определены в `CONTEXT.md`.
