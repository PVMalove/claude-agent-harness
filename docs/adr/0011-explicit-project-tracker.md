# Явный трекер проекта в проектном конфиге

## Контекст системы

Харнесс ведёт тикеты, ветки и PR/MR целевого репозитория через CLI трекера (`gh`, `glab`).
Эвристика по URL `origin` (`github.com` или хост с `gitlab.`) не выдерживает self-hosted GitLab:
порт в HTTPS- и `ssh://`-URL попадает в slug, подгруппы обрезаются, хост без `gitlab.` в имени
считается локальным трекером. Кроме того, `glab` сам выбирает remote в порядке
`upstream` > `gitlab` > `origin`. Трекер проекта — общее знание команды, которое коммитится
вместе с проектом, а не состояние машины разработчика.

## Действующий контракт

Вводится в 1.3.0. `.harness/project.json` принимает необязательное поле
`tracker: {type, host, project}`: `type` — `github`, `gitlab` или `local`; `host` включает порт
(`gitlab.example.test:4443`); `project` — полный путь с подгруппами (`group/sub/project`).
`project.schema.json`, `project.json.tmpl` и `validate_project_json` меняются как один контракт.

Если поле задано, оно — единственный источник трекера для `harness health`, hooks, скиллов и
отчётности. Без поля действует fallback: разбор `origin` с учётом схемы, userinfo, порта и
подгрупп. Все вызовы `gh` и `glab` адресуют проект явно через `-R`, собранный из трекера
проекта; `glab api` получает хост через `GITLAB_HOST=<host>`, потому что `glab` отклоняет
порт в `--hostname`. CA-сертификаты, прокси и токены остаются в личной
конфигурации CLI и в `project.json` не попадают. При `type: gitlab` health требует
`glab` не ниже 1.117.0.

`harness install`, создавая `project.json`, предлагает значения из `origin` как значения по
умолчанию и принимает их флагами. Существующий `project.json` — seed-файл проекта — не
переписывается.

## Операционные последствия

Проекты без поля продолжают работать; health сообщает warn с готовым сниппетом, а при
расхождении поля и `origin` — warn о расхождении, при этом побеждает поле. Отклонены:
только исправленный разбор URL (не покрывает хосты без `gitlab.` и выбор remote в `glab`) и
обязательное поле (ломает все установленные проекты). Тесты, fixtures и документация
используют только нейтральные примеры хостов и проектов.
