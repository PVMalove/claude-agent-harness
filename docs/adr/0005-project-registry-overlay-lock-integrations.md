# `harness registry`/`lock-project-skills`/`.harness/integrations.json` портированы из апстрима, а не изобретены заново

Апстрим (PR #2/#3, смерджены 20–21.08 — уже после точки форка этого репозитория 19.08) добавил три независимых от модели composition механизма: генерацию `.harness/skills/REGISTRY.md` в целевом проекте (фоллбек-обнаружение для рантаймов без нативного project-скилл-рута, сейчас — Hermes), hash-provenance для скиллов, которыми проект владеет напрямую под `.harness/skills` вне любой выбранной capability (`.harness/overlays/project-local.lock`), и инвентарь нативных MCP/plugin/hook/runtime-конфигов с sha256 и именами секретных env-переменных (`.harness/integrations.json`). `harness health` теперь проверяет все три, плюс нерешённые `{{...}}`-маркеры в `AGENTS.md`.

Портировано без изменения архитектуры: `extends`/`overrides`/`additions` (docs/adr/0001) резолвит capability из `skills/` этого репозитория — скиллы, которыми владеет сам целевой проект, там по определению не лежат, так что им нужен отдельный provenance-механизм независимо от того, как устроена composition. Второй пункт был реальной, а не гипотетической дырой: `global-skills/start-project/SKILL.md` уже требовал от агента «keep their provenance and hashes in a versioned overlay lock», а команды для этого не существовало.

`.claude/settings.local.json` (файл, который `pvmalove-suite` сам разворачивает в целевой проект для hook-wiring) включён в `known_paths` для `.harness/integrations.json` с самого начала, а не отложен: `pvmalove-suite` пока установлен только в этом репозитории (и то — в gitignore'нутом self-test `.harness/` в корне, не в реальном закоммиченном проекте), так что миграционной базы, которую можно было бы сломать, не существует. `scaffold_pvmalove_extras` сама пишет соответствующую запись в `.harness/integrations.json` в момент первого создания `settings.local.json`, так что интеграция остаётся заинвентаризированной без ручного шага.

`validate_overlay_locks` перенесена целиком, включая ветку валидации remote+revision (с проверкой credentials в URL) — хотя `cmd_lock_project_skills` пишет только `project-local`-локи. В апстриме то же самое: валидатор рассчитан на локи, написанные вручную или сторонним инструментом, не только тем, что есть в этом репозитории.

**Rejected**: не портировать REGISTRY.md-механизм, раз у этого репозитория нет собственного личного Hermes-оверлея для проверки. Отклонено — `docs/runtime-discovery.md` и `bin/install-global --runtime hermes` уже обещают поддержку Hermes для любого пользователя харнесса, не только автора; без REGISTRY.md это обещание не выполнялось.
