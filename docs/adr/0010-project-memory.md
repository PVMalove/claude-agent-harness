# Память проекта в Context Package

## Контекст системы

Прошлые решения и фиксы проекта лежат в ADR, глоссарии, архиве задач, закрытых тикетах, PR,
Completion report, QA findings и Lifecycle ledger, но Context Package находит только ADR по
ключевым словам. Поиск по смыслу требует индекса и модели эмбеддингов, а Context Package обязан
оставаться immutable, детерминированным, без LLM и без сетевых вызовов при сборке. Текст тикетов
и отчётов пишут люди и агенты, поэтому для брифа разработчика он недоверенный. Эпик: #420.

## Действующий контракт

Память проекта — выводимый кэш, а не источник истины. Истина остаётся в исходных артефактах;
индекс можно удалить и пересобрать командой `harness memory rebuild` без потерь. Агент не пишет
в индекс напрямую: новые записи появляются только через артефакты корпуса.

Память — opt-in capability целевого проекта: `memory.enabled` и `memory_policy` в проектном
конфиге. Политика deny-by-default: индексируются только разрешённые типы и пути источников,
с redact-правилами; QA findings и ledger попадают только в санитизированной форме. Coordinator
принимает per-dispatch `--no-memory`.

Сборка Context Package один раз выполняет поиск по цели и DoD тикета и замораживает хиты в
пакете как указатели: заголовок, статус источника, путь, hash источника и причина включения.
Текст источника в пакет не попадает. Freshness пакета сверяет hash источников замороженных
хитов, а не состояние индекса, поэтому недетерминизм поиска не нарушает immutability. Хиты
ограничены `min_similarity`, top-k, квотами слотов по типу источника и токен-потолком внутри
бюджета Package. Superseded-источники не выдаются, остальные исторические помечаются как
требующие проверки.

Ingest локальных файлов ленивый и инкрементальный по content-hash перед поиском. Данные трекера
попадают в корпус только явной командой `harness memory sync` в локальный санитизированный
снапшот; сборка Package сетевых вызовов не делает. Индекс один на репозиторий, живёт в главном
checkout, worktree читают его read-only. Индекс записывает модель и hash источников; их смена
требует пересборки. Если индекса, модели или bundle нет, Package собирается без памяти с явной
причиной деградации.

Локальный FTS5-кэш расположен в `.harness/.sandboxes/cache/memory/` главного checkout;
его policy и исходные файлы, включая разрешённый gitignored архив, общие для worktree.
`build` и `rebuild` отклоняют запуск из связанного worktree до создания файлов и используют
общую межпроцессную SQLite-блокировку, отдельную от заменяемого индекса. При недоступности Git
операции памяти в checkout с `.git`-файлом не создают собственный кэш; остальные потребители
общего storage resolver сохраняют прежний fallback. Для отдельного Git-каталога главный checkout
должен быть явно задан общим `core.worktree`: путь проверяется на существование и связь с главным
Git-каталогом, а неверная привязка отклоняется операциями памяти. Без `core.worktree` Git-каталог
с именем `.git` неотличим от обычного `<main>/.git`; такой отдельный layout не поддерживается и
требует настройки `core.worktree` до работы с памятью.

Поиск гибридный: SQLite FTS5 и вектор через `sqlite-vec` с локальной многоязычной моделью,
слияние по рангу. Веса модели скачиваются один раз по URL из lock-файла и проверяются по
SHA-256, не хранятся в Git и в пакете. `min_similarity` применяется к cosine до слияния и
калибруется на golden-наборе под pinned-модель. Векторный слой поставляется вторым срезом и
только при измеримом выигрыше над FTS5 на golden-наборе; до этого память работает на FTS5.

`harness memory search` в главном checkout лениво обновляет только производный локальный
кэш перед read-only query. Это явное уточнение CLI-контракта #423: он может создавать cache/lock
files и ждать writer до 2 секунд. Raw API `harness.memory.search` и search в linked worktree
остаются read-only; writer использует только конфиг/источники main. Ошибка refresh возвращает
пустые указатели с диагностикой, сохраняя прежний кэш; corrupt cache требует explicit rebuild.
Указатель содержит date/superseded_by и `history_to_verify: true` для всех non-superseded
источников. QA/ledger — только ограниченные безопасные проекции выбранной generation v3,
без commands/prompts/approvals/произвольного JSON; backend-orchestration не обязательна.
Роли оркестрации search не получают. Completion report получает опциональные поля `lessons`
(без повышенного веса, статус «не подтверждено человеком») и `used_memory` (слабый сигнал).
Оба поля — опциональные списки непустых строк, пустые списки допустимы. `used_memory` не
разрешается против текущего индекса и не влияет на приём отчёта или поисковый вес.
Для lessons нужен отдельный opt-in `completion_report` вместе с allow_paths на `reports/*.json`
выбранной generation: индексируется только bounded sanitized projection, не весь отчёт.
При одновременном opt-in QA evidence сохраняется, но указатель с lessons всегда имеет
неподтверждённый статус. Версия ledger и обязательные поля Completion report не меняются.

## Операционные последствия

Срез #428 реализует явный `harness memory sync <repo>` только из main checkout через `gh api`
или `glab api` по существующему origin routing. Санитизированные immutable records живут отдельно
от индекса в `.harness/.sandboxes/memory/snapshot/`; atomic manifest выбирает активный корпус.
Закрытые тикеты и PR/MR используют существующий `task_archive` с `record_kind`, удалённые отчёты —
отдельный opt-in `completion_report` и точный marker из project-memory guide; lessons для них
не обязательны. Локальный lessons-only контракт ledger сохраняется, enum политики не расширяется.
Полный bounded inventory сверяет исчезновение/reopen; одинаковые hashes сохраняют байты/mtime.
Лимиты: 20 страниц/1000 записей на endpoint, 200 запросов/1000 активных записей на sync,
4 MiB stdout+stderr и 10 секунд на запрос. Частичный inventory не публикуется. Fetch/parse/policy
race сохраняют прежний manifest/index; index failure после публикации имеет отдельный статус и
восстанавливается offline build/rebuild. Старые неактивные файлы остаются без автоматической GC;
ticket и PR делят квоту task_archive. Snapshot и index имеют последовательные commit points,
Context Package остаётся offline. Эти ограничения приняты вместо watermark/retention-политики.

Проекты без `memory.enabled` не меняют поведение и бюджет Package. Схема Package и контракт
Completion report получают новые поля, а схема проектного конфига и `validate_project_json`
меняются вместе. `harness health` показывает размер индекса, число источников и статус модели
и остаётся read-only. Качество памяти подтверждается golden-набором из реальных закрытых
тикетов с гейтом recall@k и потолком нерелевантных хитов; изменение модели, порога или квот
требует повторного прогона. Векторный срез требует проверки `sqlite-vec` и модели на Windows,
WSL и CI. Повысить вес урока может только мейнтейнер, перенеся его в ADR.

В FTS5-срезе секция «Память проекта» в `harness health` и его `--json`-отчёте содержит
проверки `memory.index` и `memory.model`. Выключенная память или пустой allowlist дают
`skipped`; отсутствующий, повреждённый или несовместимый со схемой/политикой индекс — `warn`
с командой `harness memory rebuild` для главного checkout. Валидный индекс получает `ok`
с размером в байтах и числом индексированных источников. Отсутствие модели отдельно отмечается
как `skipped`: FTS5 работает без модели до подключения векторного среза. Проверки читают общий
индекс из worktree, не создают кэш, не скачивают модель и не пересобирают индекс даже с `--fix`.
Экран диагностики Harness console использует тот же health-отчёт.
