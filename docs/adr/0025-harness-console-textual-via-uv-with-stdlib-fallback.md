# Harness console: TUI на textual через `uv run --with` с запасным stdlib-режимом

Статус: proposed (принимается после одобрения PR по спецификации harness console).

## Контекст системы

Код харнесса, который копируется в целевые проекты, использует только stdlib: у харнесса нет своего
окружения (`dependencies = []`), а диагностика должна работать и на машине, где зависимости ещё не
установлены или сломаны. Интерактивному пульту `harness console` нужен полноценный TUI (панели,
деревья, поиск), а `curses` на Windows в stdlib отсутствует.

## Действующий контракт

- `harness console` получает textual/rich во временном окружении uv:
  `uv run --with textual==<pin>` перезапускает пульт, не меняя зависимостей целевого проекта.
  Версия закреплена в коде харнесса.
- Если uv недоступен или textual установить нельзя (нет сети), пульт сообщает причину и выводит
  stdlib-отчёт `harness health`. Диагностика никогда не зависит от textual.
- Логика проверок и команд живёт в stdlib-коде (`harness health`, CLI харнесса и coordinator).
  Пульт только показывает результаты и вызывает эти функции, поэтому неинтерактивные пути (CI,
  агенты) от textual не зависят.

Отклонённые варианты: только stdlib (нумерованное меню или `msvcrt`/`termios` дают бедный интерфейс
при двух платформенных реализациях), закреплённый offline wheelhouse textual по образцу parser bundle
(второй bundle, который надо собирать и публиковать), обязательная ручная установка (лишний шаг, и
пульт недоступен именно тогда, когда он нужнее всего).

## Операционные последствия

- Первый запуск пульта требует сети или кэша uv. Офлайн-машина получает текстовый отчёт health.
- Обновление textual — это смена pin в коде харнесса и проверка TUI-тестов.
- Тесты проверок и команд идут без textual. TUI-тесты запускаются в окружении с textual.
