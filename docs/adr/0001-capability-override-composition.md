# Персональная capability расширяет чужую через extends/overrides/additions, а не дублирует её список целиком

Апстримный `harness/bin/harness` разрешает капабилити как плоский список путей (`CAPABILITIES.json[name].skills`) и падает с `duplicate skill name`, если выбранные капабилити дают два разных исходника с одним именем — то есть `mattpocock-suite` и первую версию `pvmalove-suite` (со своим полным списком из 27 путей, включая 19 прямых ссылок на vendor) нельзя было выбрать одновременно, а держать 19 вручную дублированных vendor-путей в отдельном JSON означало бы расхождение при каждом обновлении апстрима.

Решили расширить схему `CAPABILITIES.json` и резолвер путём в `harness/bin/harness`: капабилити может иметь `extends` (имя базовой капабилити), `overrides` (имя скилла → first-party-путь, подменяет исходник по имени) и `additions` (список новых first-party-путей). `pvmalove-suite` = `mattpocock-suite` + 6 overrides + 2 additions, без единой продублированной строки.

**Rejected**: статичная капабилити с полным списком 27 путей (проще для чтения, но требует ручной синхронизации с апстримом при каждом обновлении mattpocock-suite — отклонено как источник дрейфа).
