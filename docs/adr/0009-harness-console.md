# Harness Console

## Контекст системы

Интерактивная диагностика показывает health, команды и состояние оркестрации, но
устанавливаемый харнесс не должен менять зависимости целевого проекта ради интерфейса.
Базовая проверка здоровья обязана работать при отсутствии TUI-библиотеки и сети.

## Действующий контракт

`harness console` запускает закреплённую в `harness/console/pin.py` версию Textual через
`uv run --with textual==<pin>` на том же Python, не правя lock или зависимости целевого
проекта. Launcher решает, нужен ли повторный запуск с Textual; модули экранов импортируют
Textual только внутри TUI-пути. Содержимое экранов берётся из stdlib-команд `harness health`,
coordinator и других CLI, поэтому пульт не создаёт параллельной логики проверок.

Если `uv` отсутствует в PATH или запуск Textual не удался, CLI сообщает причину и печатает
тот же текстовый отчёт, который выдаёт `harness health`. Ошибка уже запущенного TUI
возвращает его код завершения без повторного текстового отчёта: это сбой интерфейса, а не
невозможность получить зависимость.

## Операционные последствия

Неинтерактивная диагностика, агенты и CI не зависят от Textual. Первый интерактивный
запуск требует доступа к пакету или кэша `uv`; офлайн-путь сохраняет health-отчёт.
Обновление pin требует проверки launcher, fallback и экранов.
