ПРЕДЛОЖЕНИЕ / ISSUE 716

Консоль становится
окном работы агента.

Сейчас adapter создаёт скрытый процесс, а координатор видит преимущественно состояния ledger. Предлагается связать dispatch с реальной runtime-сессией и вывести её ход работы в раздел «Оркестрация».

Открыть исходный тикет ↗
01

Проверить среду до запуска

Права на Git metadata, ledger, inbox и caches проверяются там, где будут работать инструменты worker. Постоянный отказ исключает повтор того же запуска.

02

Показать работу сразу

Сессия открывается в консоли по умолчанию. Видны роль, worktree, текущая операция, вывод и запросы разрешений. Скрытый фон — явный выбор.

03

Восстановить без догадок

Первый self-report имеет собственный срок ожидания. Retry возможен после доказанного исхода процесса, в пределах бюджета и сохранённого контракта.

04

Не тратить токены на наблюдение

События runtime читает обычный локальный код. Открытие панели, обновления и reconnect не вызывают LLM и не меняют контекст агента.

Один каркас по #711

Одобренный монитор встраивается в существующую Textual-консоль: общие TopBar, Footer, тема, меню и контекст batch. Контейнерный маршрут и восстановление переиспользуют этот каркас. Recovery открывается из выбранного batch, а не становится обязательным шагом после очистки. HTML не является отдельным продуктом.

Как это связано

Поток наблюдения: runtime events → локальный монитор → интерфейс консоли. Coordinator-модель в этой цепочке не участвует. Подключение не создаёт второго worker и не меняет штатные разрешения runtime.

  • Закрытие окна наблюдения сохраняет worker.
  • Остановка требует отдельного подтверждения.
  • При потере связи состояние процесса остаётся неизвестным.
  • Принятый access plan не меняется скрытым fallback.

Границы реализации

  • workflow/delivery.py сохраняет receipt и связывает наблюдение с dispatch.
  • startup.py различает отсутствие процесса, живой worker и неизвестность.
  • screens/orchestration.py получает рабочие сессии и живую ленту.
  • Adapter использует проверенный native session API или потоковый протокол.
  • Retry, аудит и бюджеты остаются в ядре orchestration.

Ноль дополнительных токенов

Монитор отображает уже существующие события, stdout и статусы. Ни один просмотр, фильтр, таймер обновления или reconnect не обращается к модели. Нет дополнительного агента, progress-prompts или LLM-пересказов логов.

Рабочие вызовы самого агента и ролевые handoff сохраняют свой расход. Автоматическая отправка ленты в контекст координатора исключена. Если человек отдельно просит модель разобрать лог, это отдельное действие с расходом токенов.

Критерий готовности

Пользователь открывает «Оркестрация → Сессии» и без поиска файлов видит, что делает worker. При отказе среды видит точную причину ещё до запуска. При permission request видит действие, которое требуется от него. При разрыве связи консоль сообщает неизвестность и не создаёт повторный процесс. При открытой и закрытой панели число рабочих LLM-вызовов и передаваемые модели сообщения одинаковы.

Это локальный макет, а не подключённая консоль. Сценарии и состояния worker в макете условные. Код механизма запуска не изменён; причина старого инцидента #555 окончательно не установлена.
