Правила доски

Доска — проекция трекера и ledger. Статус тикета пишут /implement, /fast-implement, /to-pull-requests и человек через перенос карточки. Других источников статуса нет.

Спеки

Одна доска на спеку (эпик). GitHub: открытые issue с sub-issues. GitLab: issue, на которые ссылается маркер ## Parent: #N подзадач. Локальный трекер: каталоги .scratch/<feature-slug>/. Тикеты, которые создал /to-tickets, появляются на доске своей спеки при следующем обновлении.

Колонки

КолонкаТикет
Бэклоготкрыт, status::blocked или без status::*
Готово к работеоткрыт, status::ready
В работеоткрыт, status::in-progress; /implement и /fast-implement ставят метку в pre-flight
Review / QAоткрыт, status::in-progress, текущий dispatch его batch — ревью или QA, либо открыт PR/MR задачи
Готовозакрыт после подтверждённого мерджа; закрытые с resolution::wontfix не показываются

После подтверждения мерджа /to-pull-requests закрывает тикет и переводит зависимые без открытых блокеров в status::ready. Доска показывает оба перехода без перезагрузки страницы.

любая → Review / QA, любая → Готовоотказ: первую колонку вычисляют ledger и PR, вторую заполняет закрытие после мерджа
из Review / QA, из Готовоотказ: активный batch или закрытый тикет

Смена статуса — команда каталога консоли класса external-change. Сервер требует подтверждения, запускает её как мутирующий job и заменяет метку, а не добавляет вторую: на GitLab прежняя метка снимается явно, в локальном трекере меняется строка **Workflow:**. Пока идёт другая мутирующая команда, перенос получает отказ «занято: <job>». Выбор статуса в модальном окне — те же переходы для клавиатуры и узкого экрана.

Промпт агента

Метки тикетаКоманда
afk + pipeline::fast/fast-implement #N
afk + pipeline::full, или afk без pipeline::*/implement #N (полный цикл — безопасный вариант по умолчанию)
hitl/to-guide #N

После команды идут тикет, эпик, интеграционная ветка, блокеры, «What to build», критерии приёмки и Discovery Context из тела тикета. Кнопка копирует промпт целиком.

Данные и обновление

  • Снимок доски собирает слой снимков, клиент получает его по WebSocket от Сервера консоли.
  • Трекер читается через gh, glab или файлы .scratch/ с кэшем по TTL и без изменения локального состояния.
  • Кэш сбрасывают кнопка «Обновить», успешная смена статуса и событие ledger по тикету открытой доски.
  • Если трекер недоступен, доска показывает последний снимок, его возраст и причину, а перенос получает отказ.
  • Текст тикета — недоверенные данные: страница выводит его как текст и не превращает Markdown в HTML.
  • Подписи ru/en идут через слой перевода консоли. Выбранная спека запоминается в браузере зрителя.

Вне рамок

  • Доска в TUI.
  • Создание и редактирование тикетов с доски.
  • Закрытие тикета с доски и перенос в «Review / QA» или «Готово».
  • Синхронизация с GitHub Projects и досками GitLab.
