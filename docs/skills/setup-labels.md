```text
# Настройка меток

`gh issue edit --add-label`/`gh issue create --label` завершаются ошибкой для ещё не существующей метки: `gh` никогда не создаёт её автоматически. Этот навык создаёт каждую метку, необходимую таксономии triage этого репозитория, поэтому эти вызовы никогда не завершатся ошибкой из-за отсутствующей метки.

## Процесс

1. **Прочитайте таблицы.** Получите каждую строку `Label` / `Color` из `docs/agents/triage-labels.md` — таблицы таксономии (категория, режим выполнения, состояние workflow, контекстные метки) и дополнение Wayfinder. Только имя и hex-цвет, пропустите столбцы `Meaning`/`Applied by`. Если файла нет, попросите пользователя сначала запустить `/setup-matt-pocock-skills` и остановитесь.
2. **Покажите план.** Перечислите каждую метку, которая будет создана или обновлена, вместе с её цветом. Подтвердите с мейнтейнером до изменения GitHub: это меняет общее состояние репозитория и требует той же дисциплины, что любой шаг этого репозитория, изменяющий tracker (см. `docs/agents/issue-tracker.md`).
3. **Примените.** Для каждой метки выполните `gh label create "<name>" --color "<hex>" --force`. `--force` делает операцию идемпотентной: он обновляет цвет уже существующей метки вместо ошибки и не затрагивает ничего другого (issues, уже содержащие эту метку, не меняются).
4. **Сообщите.** Одна строка на метку: создана, обновлена (цвет изменён) или уже корректна (no-op). Не печатайте повторно полный план из шага 2.
```

## 3. Контракты

- **Вход (Input/Brief):** `docs/agents/triage-labels.md` и явное подтверждение мейнтейнера.
- **Выход (Output/Report):** по одной строке результата для каждой метки.
