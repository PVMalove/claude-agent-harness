```text
# Настройка меток

`gh issue edit --add-label`/`gh issue create --label` завершаются ошибкой для ещё не существующей метки: `gh` никогда не создаёт её автоматически. GitLab поступает наоборот: `--label` с отсутствующей меткой молча создаёт её с цветом GitLab по умолчанию, поэтому метка, поставленная тикету до запуска этого навыка, остаётся с неправильным цветом. Этот навык создаёт каждую метку, необходимую таксономии triage этого репозитория, с её каноническим цветом, поэтому запускайте его до первого `/to-spec` или `/to-tickets`.

## Процесс

1. **Прочитайте таблицы.** Получите каждую строку `Label` / `Color` из `docs/agents/triage-labels.md` — таблицы таксономии (категория, режим выполнения, состояние workflow, контекстные метки) и дополнение Wayfinder. Только имя и hex-цвет, пропустите столбец `Applied by`; на GitHub пропустите и `Meaning`, а на GitLab сохраните его первое предложение как описание метки. Если файла нет, попросите пользователя запустить `harness update` — он создаёт файл из шаблонов харнесса — и остановитесь.
2. **Покажите план.** Перечислите каждую метку, которая будет создана или обновлена, вместе с её цветом. Подтвердите с мейнтейнером до изменения трекера: это меняет общее состояние репозитория и требует той же дисциплины, что любой шаг этого репозитория, изменяющий tracker (см. `docs/agents/issue-tracker.md`).
3. **Примените.**
   - **GitHub:** для каждой метки выполните `gh label create "<name>" --color "<hex>" --force`. `--force` делает операцию идемпотентной: он обновляет цвет уже существующей метки вместо ошибки и не затрагивает ничего другого (issues, уже содержащие эту метку, не меняются).
   - **GitLab:** у CLI нет `--force` для создания метки, поэтому сначала сравните с существующими метками. `<host>`, `<project-url>` и `<project-id>` определены в `docs/agents/issue-tracker.md` → GitLab → Conventions.
     - Прочитайте существующие метки один раз: `GITLAB_HOST=<host> glab api --paginate projects/<project-id>/labels` — через постраничный API, потому что собственный список меток CLI возвращает одну страницу. Каждая запись содержит `id`, `name` и `color`.
     - Отсутствующая метка: `glab label create -R <project-url> -n '<name>' -c '<hex>' -d '<description>'`. `<description>` — первое предложение столбца `Meaning` простым текстом, без backticks и кавычек: внутри двойных кавычек shell выполнил бы слово в backticks как команду, а значение в одинарных кавычках не может содержать кавычку.
     - Существующая метка с другим цветом (hex сравнивается без учёта регистра): `glab label edit -R <project-url> --label-id <id> -c '<hex>'`, где `<id>` взят из списка. Меняется только цвет; issues, уже содержащие метку, не меняются.
     - Существующая метка с тем же цветом: no-op.
4. **Сообщите.** Одна строка на метку: создана, обновлена (цвет изменён) или уже корректна (no-op). Не печатайте повторно полный план из шага 2.
```

## 3. Контракты

- **Вход (Input/Brief):** `docs/agents/triage-labels.md` и явное подтверждение мейнтейнера.
- **Выход (Output/Report):** по одной строке результата для каждой метки.
