````text
# Статистика поставки

**Цель:** после завершения эпика и его дочерних тикетов сообщить, во что фактически обошлась поставка, — в виде автономной HTML-панели и краткого резюме в этой сессии.

Только чтение. Скил читает локальные транскрипты сессий, историю git этого репозитория и трекер задач, записывает один HTML-файл и никуда ничего не отправляет.

## Маршрут

Инструмент поставляется с harness по пути `.harness/reporting/delivery_stats.py`. Если его нет, этот проект не установил предоставляющую его возможность — сообщите об этом вместо повторной реализации здесь.

```bash
python .harness/reporting/delivery_stats.py --repo . --epic <номер> \\
  --html docs/reports/epic-<номер>.html
```

Добавьте `--json`, когда разработчику нужны исходные числа вместо резюме. `--rates <file>` переопределяет тарифную карточку; `--base <ref>` переопределяет базу diff.

После сопоставимого завершённого эпика сохраните versioned baseline, а при следующем отчёте передайте
его в `--baseline`. Сравнение попадёт и в terminal/JSON-вывод, и в HTML-дашборд:

```bash
python .harness/reporting/delivery_stats.py --repo . --epic <baseline-epic> \\
  --save-baseline docs/reports/epic-<baseline-epic>.baseline.json
python .harness/reporting/delivery_stats.py --repo . --epic <current-epic> \\
  --baseline docs/reports/epic-<baseline-epic>.baseline.json \\
  --html docs/reports/epic-<current-epic>.html
```

## Процедура

1. **Определите эпик.** Его называет разработчик. Если он называет дочерний тикет, всё равно запустите инструмент для этого тикета — инструмент считает тикет без подзадач областью из одного элемента — и сообщите, что вы это сделали.
2. **Проверьте тарифную карточку, прежде чем обещать деньги.** Стоимость появляется только тогда, когда существует `.harness/reporting/rates.json` и в нём указаны цены для использованных моделей. Встроенного прайс-листа намеренно нет: цены зависят от тарифа и меняются со временем. Если файла нет, скопируйте `.harness/reporting/rates.example.json`, скажите разработчику заполнить собственные тарифы и пока сообщите всё остальное — не придумывайте число и не называйте цену, которую не прочитали из этого файла.
3. **Сохраните или сравните baseline, когда это уместно.** Сохраняйте только завершённый эпик,
   сопоставимый с измеряемым. Для обеих сторон comparison сохраняет attribution `exact` либо
   `estimated`; разница появляется только если telemetry есть с обеих сторон.
4. **Запустите инструмент** и запишите панель в `docs/reports/`.
5. **Сообщите резюме** в этой сессии: закрытые тикеты, объём кода, токены по моделям, разбиение кэша, стоимость при наличии тарифов и путь к HTML.
6. **Сохраняйте оговорки, не сглаживайте их.** В них смысл отчёта:
   - Работа Claude Code атрибутируется **точно** — каждая запись транскрипта содержит свою ветку.
   - Работа Codex атрибутируется **приблизительно** — его журналы не содержат ветку, только рабочую директорию и временную метку, поэтому итог включает этот репозиторий в окне активности эпика и может включать несвязанную работу того же периода. Всегда говорите «оценка», когда приводите это значение.
   - Всё, что инструмент не смог получить из источника, обозначается `нет данных`. Повторите это как отсутствующие данные; никогда не округляйте до нуля и не заполняйте по памяти.
   - ADR считается добавленным только тогда, когда коммит, впервые добавивший файл, принадлежит одному из pull request эпика, поэтому squash-merged pull request даёт заниженную оценку. Упомяните это только если разработчик спросит, почему число выглядит низким.
7. **Предложите прикрепить отчёт.** Панель — локальный файл; публикация её в эпике — решение разработчика, а не автоматический шаг.

## Границы

Не редактируйте транскрипты, тарифную карточку или историю git, чтобы число выглядело лучше. Не добавляйте цены, модели или тикеты, которые инструмент не сообщил. Если инструмент завершился с ненулевым кодом, покажите его stderr и остановитесь — частичная статистика, представленная как полная, хуже отсутствия статистики.
````

## 3. Контракты

- **Вход (Input/Brief):** номер завершённого эпика либо дочернего тикета; необязательные параметры `--json`, `--rates` и `--base`.
- **Выход (Output/Report):** HTML-панель в `docs/reports/` и краткий отчёт с закрытыми тикетами, объёмом кода, токенами, кэшем, стоимостью (если она рассчитана) и оговорками достоверности.
