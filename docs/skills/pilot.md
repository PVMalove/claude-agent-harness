# Pilot — Пилотная базовая линия

Источник: [`harness/orchestration/pilot.md`](../../harness/orchestration/pilot.md).

## 1. Название и локализация

- **Английское название:** `Pilot`
- **Русский перевод:**

```text
Пилотная базовая линия
```

## 2. Полный перевод исходного документа

````text
# Пилотная базовая линия backend-оркестрации

Это руководство фиксирует первую наблюдаемую базовую линию для необязательной возможности `backend-orchestration`. Это протокол наблюдения для координатора, а не механизм dispatch или политика производительности.

## Назначение

Собрать сопоставимые доказательства из реально завершённых batch до решения о необходимости будущих целей или изменений процесса. Используйте одну и ту же рабочую таблицу и правила подсчёта весь период наблюдения.

## До первого запуска

1. Выберите период наблюдения и запишите его метки начала и конца.
2. Определите, откуда будут поступать доказательства: записи batch, completion reports, журналы quality gate и трекер задач. Зафиксируйте недоступные источники до начала периода.
3. Запишите ID batch, ID тикета, issue-ветку, последовательность ролей и состояние завершения для каждого batch в области наблюдения.
4. Объявите окно наблюдения после интеграции и правило проекта о серьёзности дефектов.
5. Подготовьте одну строку рабочей таблицы на batch и одну сводную строку на закрытый тикет. Не заполняйте отсутствующие измерения оценками.

## Период наблюдения

Для каждого закрытого тикета в периоде применяйте одни и те же правила:

- считайте каждый старт роли стартом, а повтор — стартом нового dispatch;
- относите заявленные входные и выходные токены к dispatch, который их создал; помечайте данные токенов как отсутствующие, когда среда выполнения их не сообщает;
- записывайте прошедшее время запуска quality gate отдельно от времени очереди или ожидания;
- свяжите каждый дефект после интеграции с его batch и последовательно применяйте объявленные окно наблюдения и правило серьёзности;
- сохраняйте с рабочей таблицей период измерения, ID batch/тикета, источник, заметки об отсутствующих данных и единые правила подсчёта.

## Запись каждого batch

Зафиксируйте следующее до закрытия записи batch:

- ID batch и тикета, запущенные роли, ID dispatch и наличие повторного dispatch;
- число токенов каждого dispatch, когда оно доступно, с источником и заметкой об отсутствии данных;
- метки времени старта и результата quality gate, а также время очереди, когда оно доступно;
- метку времени интеграции и все связанные ID дефектов, наблюдённые в объявленном окне.

## Измерение quality gate

Используйте метки времени, выданные сериализованной линией quality gate. Рассчитывайте wall time от старта gate до его результата и ведите время очереди отдельным наблюдением. Если любая метка времени недоступна, зафиксируйте пробел вместо реконструкции по несвязанным событиям.

## Запись дефектов после интеграции

Во время объявленного окна наблюдения записывайте каждый дефект, который можно связать с batch. Включайте ID batch, ID дефекта, метку времени обнаружения, серьёзность по правилу проекта и источник доказательств. Не считайте несвязанный дефект или дефект вне окна без документирования причины его включения.

## Рабочая таблица базовой линии

| Измерение | Требуемое наблюдение | Источник / заметка об отсутствующих данных |
| --- | --- | --- |
| Старты агента на закрытый тикет | Старты и повторы для каждого закрытого тикета | Записи batch и ID dispatch |
| Токены на batch | Заявленные входные и выходные токены для каждого dispatch | Completion reports или записи выполнения |
| Wall time quality gate | От старта gate до результата, с отдельной очередью | Метки времени quality gate |
| Дефекты после интеграции | Связанные дефекты в объявленном окне по правилу серьёзности | Трекер задач и записи дефектов |

Полученная базовая линия — доказательство для будущих решений. Это руководство не предписывает именованного провайдера, модель, runtime или платформу, а также жёсткую числовую цель.
````

## 3. Контракты

- **Вход (Input/Brief):** период наблюдения, закрытые batch/тикеты, completion reports, журналы quality gate, трекер и правило серьёзности дефектов.
- **Процесс (Process):** собрать одинаковые наблюдения без оценок отсутствующих данных и отделить время очереди от времени выполнения.
- **Выход (Output/Report):** рабочая таблица базовой линии с четырьмя измерениями и отмеченными пробелами данных.
