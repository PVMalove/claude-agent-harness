# require-bounded-check.sh — ограниченный вывод проверок

## 1. Название и локализация

- **Исходный хук:** [`harness/project/hooks/require-bounded-check.sh`](../../harness/project/hooks/require-bounded-check.sh)
- **Русский перевод:** требование ограниченного вывода полного тестового прогона.

## 2. Полное описание

Хук `PreToolUse(Bash)` читает команду из входного JSON. Если в проекте нет
`.harness/project.json`, он ничего не блокирует. При наличии конфига он проверяет команды из
`qa_gate_commands`, полный `pytest` и полный `python -m unittest`. Для такого прогона требуется
обёртка `qa-gate/scripts/test_summary.py`, которая сокращает и очищает вывод перед передачей в
историю сессии. Точечный `pytest` с node ID `::` и `unittest` с полным dotted-путём теста
проходят без обёртки.

Упоминание имени запуском не считается. Общий shell-парсер `pr_commands.py` сохраняет границы
аргументов, разбирает простые команды, вложенные оболочки и исполняемые подстановки. Текст DoD в
`gh issue create --body`, описание `glab issue create`, сообщение `git commit`, аргументы
`echo`/`printf` и команд чтения не считаются запуском проверки. Комментарии и буквальный текст
heredoc также пропускаются. Реальный запуск через `bash -c`, `eval`, `timeout`, `find -exec`,
`$(...)`, обратные кавычки, process substitution или heredoc оболочки блокируется. Неразбираемый
исполняемый текст и код интерпретатора проверяются консервативно по подстроке.

## 3. Контракт

- **Вход:** Bash-команда в stdin и `.harness/project.json` целевого проекта; для разбора нужен
  Python 3.10+ и соседний `pr_commands.py`; ошибка Python или модуля при наличии конфига даёт код `2`.
- **Выход:** код `0` для разрешённого вызова; код `2` и команда исправления в stderr для
  полного прогона без обёртки.
