## 1. Название и локализация

- **Английское название:** block-public-attribution
- **Русский перевод / Суть:**

```text
Блокировка AI-атрибуции в публичных Git-метаданных
```

## 2. Полное описание

Скрипт срабатывает на этапе `PreToolUse` для инструмента `Bash`. Его цель — гарантировать, что все Git-коммиты, Pull Request'ы и Merge Request'ы, отправка изменений (push) и тексты трекера (issue, комментарии, notes) на GitHub и GitLab не содержат автоматической атрибуции: упоминаний об использовании ИИ-ассистентов (таких как Claude, ChatGPT, Copilot, Gemini и др.), trailer "Co-authored-by: AI" и ссылок на сессии (session URLs).

Проверка работает в два уровня:
- **Git-метаданные** — commit messages, title и body PR/MR. Здесь действует полный список запрещённых терминов `FORBIDDEN`: имена моделей и runtime, атрибуция, session URL.
- **Текст трекера** — title и body issue, комментарии к issue и PR, notes к issue и MR, в том числе через `glab api`. Здесь действует только шаблон атрибуции `TRACKER_ATTRIBUTION`: trailer `Co-Authored-By`, утверждение "generated/written by <ассистент>", пометка AI-generated, ссылки на сессии ассистента. Имена runtime и пути вроде `.claude/` или `CLAUDE.md` в тикетах — словарь проекта, поэтому сами по себе они не блокируются.

Логика выполнения включает:
1. Безопасный парсинг JSON (через Python) для извлечения выполняемой команды из `tool_input.command`.
2. Вырезание тел heredoc: это stdin, а не слова команды. На месте оператора остаётся маркер, а тело проверяется, только если оператор стоит внутри проверяемого аргумента, например `-m "$(cat <<'EOF' ... EOF)"` или `--body "$(cat <<'EOF' ... EOF)"`.
3. Определение типа операции по тексту команды без тел heredoc: `git commit`, `git push`, `gh pr` и `glab mr` `create`/`new`/`edit`/`update`, `gh`/`glab issue` `create`/`new`/`edit`/`update`, комментарии `gh issue|pr comment`, notes `glab issue|mr note`, `glab api`.
4. При обнаружении этих операций скрипт использует модуль `shlex` (Python) для разбора аргументов команды. Для каждой команды публикации таблица флагов задаёт, какие короткие и длинные флаги несут текст именно в этом CLI:
   - `gh pr create|new|edit`, `gh issue create|new|edit|comment`, `gh pr comment` — `-t`/`--title`, `-b`/`--body` и файл `-F`/`--body-file`;
   - `glab mr create|new|edit|update`, `glab issue create|new|update` — `-t`/`--title`, `-d`/`--description` и файл `--description-file`;
   - `glab issue note`, `glab mr note` — `-m`/`--message`;
   - `glab api` — поля `-F`/`--field` и `-f`/`--raw-field` с ключом `body`, `description` или `title`; значение `-F key=@<path>` читается из файла.

   У gh `-d` — это `--draft`, у glab `-b` — `--target-branch`, а `-m` вне notes — milestone: такие флаги текстом не считаются. Читаются все формы: `-t X`, `-tX`, `-t=X`, кластер `-dt X`, `--title=X` и повторы флага.
5. Проверка строковых значений и содержимого указанных файлов по шаблону своего уровня. Файл должен быть доступен по literal-пути: переменная shell, `-` или `@-` (stdin) и несуществующий путь блокируют команду.
6. Для команд push и создания/редактирования PR/MR также дополнительно проверяются сообщения локальных (не отправленных) коммитов, достижимых из `HEAD` (`git log HEAD --not --remotes`).
7. В случае нахождения запрещённых подстрок или ошибки чтения файлов/строк, скрипт прерывает выполнение команды, возвращая код ошибки `2` и выводя предупреждение в stderr.

## 3. Контракты

- **Вход (Input/Brief):** JSON-объект, передаваемый на `stdin`, содержащий параметры вызова инструмента (в частности, `tool_input.command`). При необходимости читает файлы сообщений (по путям из аргументов команды) и историю локальных коммитов.
- **Выход (Output/Report):** В случае успешной проверки возвращает код `0` (команда разрешена). В случае обнаружения AI-атрибуции выводит сообщение об ошибке в `stderr` и завершается с кодом `2` (запрет выполнения). Сообщение называет уровень: Git-метаданные или текст трекера.
