## 1. Название и локализация
- **Английское название:** block-direct-master.sh (PreToolUse Hook)
- **Русский перевод / Суть:**

```text
Блокировка прямых коммитов и пушей в защищенные ветки (master, main, base_branch, integration/*) согласно правилу "Zero Direct Commits".
```
## 2. Полное описание
Скрипт является pre-hook'ом (PreToolUse) для инструмента выполнения bash-команд. Его основная задача — детерминированно обеспечивать соблюдение правила "Zero Direct Commits" (описанного в `docs/agents/git-workflow.md`), запрещая агенту внесение изменений (коммиты и пуши) напрямую в защищенные ветки.

**Логика работы:**
1. Решение принимает `direct_commits.py` по принципу fail closed: команда разрешается только при коде `0` и слове `allow` в его выводе. Отсутствие Python, любой другой код и частичная копия модуля дают код `2`.
2. Команда разбирается по токенам (`pr_commands.parse`), и в ней находится каждый вызов `git commit` и `git push`, в том числе внутри `bash -c`, `eval` и после `sudo`, `env`, `xargs`. Глобальные опции git перед подкомандой (`-C`, `-c`, `--git-dir`, `--work-tree`, `--no-pager` и другие) учитываются. Упоминание commit/push в аргументах печатающих команд (`grep`, `rg`, `echo`, `cat`), в кавычках и в теле heredoc вызовом не считается.
3. Для каждого вызова определяется каталог запуска: `cd` раньше в той же команде, иначе `cwd` из payload, иначе корень проекта (`CLAUDE_PROJECT_DIR`). Ветку спрашивает `git rev-parse` из этого каталога с теми же опциями `-C`, `--git-dir`, `--work-tree`, `--bare`, что и у вызова, поэтому проверяется ветка именно того checkout, куда попадёт коммит.
   - `cd` (а также `pushd`, `builtin cd`) учитывается, только если команда — простая цепочка, которую принимает строгий лексер (`pr_commands.strict_steps`): без `$`, обратных кавычек, скобок и комментариев. В цепочке `cd` меняет каталог последующих вызовов, если выполнится наверняка: не в конвейере (`|`) и не в списке с `||`. `cd` не первым в списке `&&` (`x && cd p`) действует только до `;`. Список, запущенный в фоне (`&`), каталог не меняет.
   - Если в команде есть `cd`, а цепочка не простая, каталог вызовов считается неопределённым. Например, `cd <wt> && git commit -m "$(cat <<'EOF' …)"` блокируется — вместо этого используйте `git -C <wt> commit -m "$(…)"`.
4. Защищенные ветки: `master`, `main`, базовая ветка проекта (`base_branch` из `.harness/project.json` корня проекта) и любые ветки с префиксом `integration/`. Commit или push из checkout на защищенной ветке блокируется.
5. Для `git push` дополнительно проверяется целевой реф каждого рефспека (например, `git push origin HEAD:master` или `git push origin feature:integration/payments`). Push в `master`, `main` или `base_branch` блокируется, даже если выполняется из issue-ветки.
6. Исключение — создание новой интеграционной ветки эпика (шаг `/to-spec`): для каждого целевого рефа `integration/<name>` скрипт через `git ls-remote` проверяет, есть ли он на remote этого checkout. Push, который только создает отсутствующие на remote `integration/*`, пропускается даже из защищенной ветки. Push в уже существующую `integration/<name>` блокируется; если remote недоступен и проверить существование нельзя, push блокируется с объяснением. Commit и другие push в той же команде проверяются как обычно.
7. Fail closed: блокируется commit/push в тексте, который не разобрать (незакрытая кавычка, код `python -c`, команды из stdin оболочки), и в команде, программу или текст для оболочки которой bash вычислит при запуске (`$X`, `sh -c "$(…)"`). Блокируется и вызов, checkout которого не определить: `cd` в путь с переменной или подстановкой, в несуществующий каталог, `cd -`, `popd`, `cd` вне простой цепочки, `GIT_DIR`/`GIT_WORK_TREE` в команде, `env -C`, путь `-C`/`--git-dir`/`--work-tree`, по которому git не находит репозиторий (например, `{}` из `xargs`).

Ограничение: слово `git` в аргументах непечатающей команды считается возможным вызовом, поэтому, например, `gh pr view --json git --jq commit` на защищенной ветке блокируется.
## 3. Контракты
- **Вход (Input/Brief):** JSON-объект вызова инструмента Bash, передаваемый через стандартный ввод (`stdin`). Используются поля `tool_input.command` и `cwd`. Переменная окружения `CLAUDE_PROJECT_DIR` (по умолчанию `.`) задает корень проекта: каталог запуска по умолчанию и место `.harness/project.json`.
- **Выход (Output/Report):** Возвращает код выхода `0`, если нарушения не найдены (разрешает выполнение команды). При попытке коммита/пуша в защищенную ветку, неразобранной команде с commit/push или неопределенном checkout возвращает код выхода `2` и выводит причину в стандартный поток ошибок (`stderr`), прерывая выполнение инструмента.
