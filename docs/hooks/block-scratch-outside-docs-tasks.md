## 1. Название и локализация
- **Английское название:** Block Scratch Outside Docs Tasks
- **Русский перевод / Суть:**

```text
Блокировка сохранения черновиков вне директории задач
```
## 2. Полное описание
Скрипт является pre-hook'ом (вызывается перед выполнением инструментов записи или редактирования файлов). Его основная цель — соблюдение стандартов хранения артефактов (согласно `docs/agents/artifacts.md` и `docs/agents/git-workflow.md`).

Внутренняя логика:
1. Считывает входные данные (в формате JSON из STDIN), из которых извлекает целевой путь файла (`file_path`).
2. Если путь файла указывает на то, что это тело PR или комментария (по наличию `pr-body`, `pr-comment`, `issue-comment` в пути):
   - Скрипт разрешает запись только в репозиторный scratch `.claude/tmp/` (например, `.claude/tmp/pr-body-<issue>-<slug>.md`) и блокирует любой другой путь, включая `docs/tasks/`. После успешной отправки через `gh`/`glab` файл удаляется; при ошибке он остаётся для повторной попытки.
3. Для всех остальных файлов (рабочие файлы, черновики, спецификации):
   - Если файл пытаются сохранить во временные системные директории (например, `AppData\Local\Temp`, `AppData\Roaming\Temp`, `/tmp/`, или `/scratchpad/`), скрипт блокирует операцию, напоминая, что спецификации и черновики задач должны храниться в `docs/tasks/`.
4. Если ни одно из условий блокировки не сработало, скрипт завершается успешно (разрешает операцию).
## 3. Контракты
- **Вход (Input/Brief):** JSON через STDIN, содержащий информацию о вызове инструмента, в том числе аргумент `file_path`.
- **Выход (Output/Report):** Код возврата `0` (разрешить выполнение инструмента), либо `2` (заблокировать) с выводом сообщения об ошибке в STDERR с указанием нарушенного правила из документации.
