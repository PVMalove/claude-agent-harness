## 1. Название и локализация
- **Английское название:** require-qa-gate.sh
- **Русский перевод / Суть:**

```text
Блокировка создания PR/MR без успешного прохождения QA
```
## 2. Полное описание
Данный хук типа `PreToolUse(Bash)` предназначен для перехвата выполнения команд в bash-терминале агента. Его основная задача — заблокировать выполнение команды `gh pr create` (создание pull request) или `glab mr create` (создание merge request), если агент предварительно не выполнил успешную проверку того checkout, чья ветка публикуется, с помощью навыка `qa-gate`.

Хук анализирует входные данные (содержимое bash-команды из stdin). Если в тексте команды есть `gh pr create` или `glab mr create` либо их алиас `gh pr new`/`glab mr new`, он определяет checkout публикуемой ветки, формирует хэш его состояния (хэш HEAD + хэш текущих изменений) и проверяет наличие и содержимое файла-маркера `.claude/.qa-gate/passed` в этом checkout. Этот маркер создается навыком `qa-gate` при его успешном выполнении. Если маркер отсутствует или его содержимое не совпадает с вычисленным состоянием, хук прерывает выполнение с ошибкой, выводя сообщение о необходимости запуска `qa-gate`. Если команда не создаёт PR/MR или проверка пройдена успешно, хук завершается с кодом 0, разрешая выполнение команды.

Ветка берётся из argv самой create-команды (разбор `pr_commands.py`); флаги других команд той же строки, например `git commit -s`, веткой не считаются:
- `gh pr create`: `--head <ветка>`, `--head=<ветка>` или короткий `-H <ветка>`, `-H<ветка>`, `-H=<ветка>` (в том числе в группе флагов, `-dH <ветка>`), префикс `owner:` отбрасывается;
- `glab mr create`: `-s <ветка>`, `-s<ветка>`, `-s=<ветка>`, `--source-branch <ветка>`, `--source-branch=<ветка>`, в том числе в группе коротких флагов (`-fs <ветка>`). Флаг glab `-H`/`--head` задаёт репозиторий (`OWNER/REPO`), а не ветку, и не учитывается;
- без флага ветки проверяется самый глубокий checkout проекта, содержащий `cwd` из payload, то есть текущая ветка.

Выбор ветки не уже, чем до #443: если в тексте есть `gh pr create`, первый `--head <ветка>`/`--head=<ветка>` во всём тексте команды (глобальный разбор `shlex.split`, как в прежнем хуке) тоже считается веткой PR и проверяется, даже если разбор по токенам create-команды не видит. `--head` без значения или текст с `--head`, который `shlex` не разобрал, блокируют вызов.

Найденной ветке должен соответствовать ровно один linked worktree, иначе вызов блокируется.

Создание PR/MR распознаётся по тексту команды: упоминание `gh pr create`/`gh pr new` или `glab mr create`/`glab mr new` в кавычках или в аргументе другой команды тоже запускает проверку checkout из `cwd`; запрет merge в `block-pr-merge.sh` на это распознавание не влияет. Блокируются и неоднозначные случаи: больше одной разной ветки (из create-команд и глобального разбора `--head`), флаг ветки без значения, create-текст, который не удаётся разобрать по токенам и в котором есть флаг ветки. Любая ошибка хука даёт код `2`, в том числе отсутствующий, неполный или синтаксически повреждённый `pr_commands.py` рядом с хуком.
## 3. Контракты
- **Вход (Input/Brief):** Входной поток (stdin), содержащий bash-команду и `cwd`. Текущее состояние git-репозитория (HEAD и незакоммиченные изменения) checkout публикуемой ветки.
- **Выход (Output/Report):** Код возврата `0` (разрешение выполнения) или код возврата `2` с выводом сообщения об ошибке в `stderr` (блокировка команды).
