## 1. Название и локализация
- **Английское название:** check-branch-name (PreToolUse Hook)
- **Русский перевод / Суть:**

```text
Валидация имени новой ветки и проверка существования связанной задачи (принцип "Issue First") перед её созданием.
```
## 2. Полное описание
Хук `check-branch-name` выполняется перед вызовом инструмента `Bash` (как PreToolUse хук). Его основная цель — не дать агенту создать ветку без привязки к существующей задаче в трекере. Он анализирует команды, передаваемые агентом, на наличие `git checkout -b` или `git switch -c`. Если такая команда обнаружена, хук выполняет следующие шаги:
1. Извлекает целевое имя ветки из команды.
2. Сверяет имя ветки с регулярным выражением `branch_pattern`, которое читается из файла `.harness/project.json` (по умолчанию `^feature/issue-[0-9]+-.+`). Если имя ветки не соответствует шаблону, выполнение команды блокируется.
3. Если имя соответствует правилам, из него извлекается первый найденный числовой идентификатор (ID задачи).
4. Воплощая принцип "Issue First", хук передаёт ID в `tracker-issue.py`. Тот определяет трекер и проект резолвером трекера проекта (`.harness/health/project_tracker.py`): поле `tracker` из `.harness/project.json`, а без него — URL `origin` с портом и подгруппами. Issue запрашивается с явной адресацией: `gh issue view <ID> -R <хост>/<проект>` или `glab issue view <ID> -R https://<хост>/<проект>`. Для локального трекера, неизвестного пути проекта, без пакета `.harness/health` или без установленного `gh`/`glab` проверка пропускается.
5. При отказе хук прерывает команду и называет причину: issue не найдена (её нужно завести через `gh issue create`/`glab issue create`, `/to-spec` или `/to-tickets`), в проекте отключены issues, CLI не авторизован на хосте трекера или проект недоступен.
## 3. Контракты
- **Вход (Input/Brief):** Строка (в формате JSON через stdin), описывающая вызов инструмента `Bash` (из которой с помощью регулярных выражений извлекается поле `command`).
- **Выход (Output/Report):** В случае успешной проверки — код `0` (разрешение на выполнение). В случае нарушения конвенции ветвления или если задачу не удалось подтвердить (не найдена, issues отключены, нет авторизации, проект недоступен, CLI не ответил за 10 с или завершился с нераспознанной ошибкой) — диагностическое сообщение с причиной в `stderr` и код возврата `2` (блокировка выполнения).
