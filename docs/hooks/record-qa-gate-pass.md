## 1. Название и локализация
- **Английское название:** record-qa-gate-pass
- **Русский перевод / Суть:**

```text
Фиксация успешного прохождения QA Gate
```
## 2. Полное описание
Скрипт `record-qa-gate-pass.sh` вызывается напрямую навыком `qa-gate` (см. `SKILL.md`) в качестве его последнего шага, сразу после успешного выполнения всех команд из `qa_gate_commands`. Так как навык выполняется в изолированном контексте (forked) и не может полагаться на надежное срабатывание хука `mark-qa-gate-passed.sh` (PostToolUse) для вызовов инструментов внутри этого fork-а, он самостоятельно записывает маркер успешного прохождения тестов.

Навык `to-pull-requests` вызывает этот же скрипт из checkout ветки PR после того, как `coordinator.py qa evidence` подтвердил текущий SHA: принятое QA-доказательство координатора записывается в маркер без повторного прогона QA-gate.

Скрипт вычисляет текущее состояние проекта, основываясь на хеше последнего коммита (`git rev-parse HEAD`) и хеше текущих незакоммиченных изменений (`git diff HEAD | git hash-object --stdin`). Полученный составной хеш состояния записывается в файл `.claude/.qa-gate/passed`, подтверждая, что текущее состояние кода прошло проверку качества.
## 3. Контракты
- **Вход (Input/Brief):** Опциональная переменная окружения `CLAUDE_PROJECT_DIR` (по умолчанию текущая директория `.`), указывающая на корневую директорию проекта. Текущая рабочая директория выбирает checkout, для которого пишется маркер, поэтому скрипт запускают из checkout тестируемой ветки или ветки PR.
- **Выход (Output/Report):** Создание или обновление файла-маркера `.claude/.qa-gate/passed`, содержащего строку вида `<HEAD_hash>:<diff_hash>`.
