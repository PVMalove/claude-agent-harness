## 1. Название и локализация
- **Английское название:** block-pr-merge (PreToolUse Hook)
- **Русский перевод / Суть:**

```text
Запрет автослияния PR/MR / Блокировка выполнения агентом команд `gh pr merge` и `glab mr merge` (включая алиас `glab mr accept`) для обеспечения ручного контроля слияния.
```
## 2. Полное описание
Данный скрипт является перехватчиком (PreToolUse хуком для Bash), который реализует политику "Zero Auto-Merge", описанную в документации рабочего процесса `docs/agents/git-workflow.md`, одинаково для GitHub (`gh`) и GitLab (`glab`).
Ответственность хука заключается в том, чтобы не дать ИИ-агенту самостоятельно завершить жизненный цикл Pull Request'а или Merge Request'а путем его слияния.

Решение принимает `pr_commands.py` по принципу fail closed: merge-текст запрещён везде, кроме команд из короткого allowlist инертных программ. Программа, которой нет в allowlist, считается способной выполнить свои аргументы или вход.

- **Нижняя граница.** Выражение `gh\s+pr\s+merge|glab\s+mr\s+(merge|accept)` без границ слов ищется в `tool_input.command` и в той же команде без переносов `\` + перевод строки — это строгое надмножество прежней проверки по подстроке. Прежняя проверка сырого payload (`"command"\s*:\s*"[^"]*gh pr merge`) тоже действует: если она срабатывает, а в разобранной команде merge-текста нет, вызов блокируется.
- **Исключение по allowlist.** Команда с merge-текстом пропускается, только если строгий лексер принимает её целиком и каждая её simple command инертна:
  - `echo`, `printf`, `cat`, `grep`, `egrep`, `fgrep`, `head`, `tail`, `wc`, `true`, `:` с любыми аргументами — только точное имя программы, без пути;
  - текстовые подкоманды: `git commit` без глобальных опций git перед `commit`; `gh issue|pr create|edit|comment|view`; `glab issue|mr create|update|note|view`.

  Всё остальное не инертно: `sort`, `rg`, `xargs`, любые обёртки, оболочки, интерпретаторы и неизвестные программы.
- **Строгий лексер** понимает небольшое подмножество bash: одинарные кавычки; двойные кавычки с экранированием `\"`, `\\` и `` \` ``; перенос `\` + перевод строки; экранирование `\` вне кавычек; разделители — перевод строки, `;`, `&`, `&&`, `|`, `||`, `|&`; перенаправления, в том числе с номером дескриптора и `>|`; here-string `<<<`; heredoc `<<` и `<<-` с разделителем в кавычках или без. Тела heredoc читаются в порядке операторов со строки после ближайшего перевода строки вне кавычек, `<<-` снимает ведущие табуляции; в argv тела не попадают.
- **Вне подмножества — блокировка.** Лексер отказывает, и команда с merge-текстом блокируется, если в ней есть `$` вне одинарных кавычек (в том числе в двойных), обратная кавычка (кроме `` \` `` в двойных кавычках), комментарий `#`, `(`, `)`, `{`, `}`, `!` и другие зарезервированные слова в позиции команды, `;;`, присваивание перед программой, подстановка процесса, незакрытая кавычка, heredoc без разделителя или тело heredoc с разделителем без кавычек, где есть `$`, обратная кавычка или `\`.
- **Merge, разбитый кавычками.** Если merge-текста в команде нет, вызов всё равно блокируется, когда слова команды (строгого лексера, а вне его подмножества — shlex) образуют `gh pr merge` или `glab mr merge`/`accept` либо одно слово содержит merge-текст после снятия кавычек.
- payload, который не разбирается как JSON или не содержит строковой `tool_input.command`, проверяется нижней границей по сырому тексту; текст только в других полях payload (например, `tool_input.description`) не учитывается.
- Python запускается на каждый вызов, без быстрого пути. Команда разрешается только при коде `0` и слове `allow` в выводе `pr_commands.py`: отсутствие Python, любой ненулевой код и частичная копия модуля дают код `2`.

Пропускаются, например, `cat <<'EOF' … EOF` (в том числе с `> notes.md`), `echo`, `printf` и `grep` с merge-текстом в аргументах, `git commit -m '…'`, `gh pr comment … --body '…'`. Блокируются упоминания в подстановке (`git commit -m "$(cat <<'EOF' … )"`), в аргументе программы вне allowlist, в обратных кавычках и в комментарии.

Остаточные ограничения — формы, которые прячут merge-текст и от проверки до #443, и от нынешней: обфускация, косвенность (через переменные или другую программу), скрипты в файлах, alias и функции оболочки, `gh alias`/`glab alias` и вызовы API (`gh api`, `glab api`).
## 3. Контракты
- **Вход (Input/Brief):** JSON-payload вызова инструмента Bash через стандартный ввод (`stdin`); решение принимается по полю `tool_input.command` и по прежней проверке сырого payload.
- **Выход (Output/Report):**
  - **Успех (Разрешение):** Код возврата `0` (пустой вывод), если в команде нет merge-текста или каждая её simple command инертна по allowlist.
  - **Отказ (Блокировка):** Код возврата `2` и текстовое сообщение в `stderr` с объяснением причины запрета, если merge-текст стоит вне инертных команд, если команда выходит за подмножество строгого лексера, если Python не найден или `pr_commands.py` не дал решения.
