## 1. Название и локализация
- **Английское название:** block-pr-merge (PreToolUse Hook)
- **Русский перевод / Суть:**

```text
Запрет автослияния PR/MR / Блокировка выполнения агентом команд `gh pr merge` и `glab mr merge` (включая алиас `glab mr accept`) для обеспечения ручного контроля слияния.
```
## 2. Полное описание
Данный скрипт является перехватчиком (PreToolUse хуком для Bash), который реализует политику "Zero Auto-Merge", описанную в документации рабочего процесса `docs/agents/git-workflow.md`, одинаково для GitHub (`gh`) и GitLab (`glab`).
Ответственность хука заключается в том, чтобы не дать ИИ-агенту самостоятельно завершить жизненный цикл Pull Request'а или Merge Request'а путем его слияния.

Решение принимается по токенам команды `tool_input.command`, а не по подстроке сырого payload. Модуль `pr_commands.py` разбирает команду на simple commands, которые bash действительно выполнит:
- цепочки и группы: `;`, `&&`, `||`, `|`, `&`, перевод строки, `( … )`, `{ …; }`, `if …; then …; fi`, перенос строки через `\`;
- подстановки `$(…)`, `` `…` ``, `<(…)`, `>(…)`, в том числе внутри двойных кавычек и в теле heredoc без кавычек;
- строки, которые исполняет другая программа: `bash -c`/`sh -c`, `eval`, `ssh`, `su`, heredoc или stdin, переданные оболочке;
- запуск через обёртки и префиксы: `VAR=1 …`, полный путь или `gh.exe`, `sudo`, `timeout`, `env`, `xargs`, `uv run`, `docker exec`, `find -exec`. Для этого каждый суффикс argv любой программы, кроме печатающих, считается возможной командой.

Блокируются `gh pr merge` и `glab mr merge`/`glab mr accept` в любой из этих позиций. Не блокируются упоминания:
- текст в кавычках как аргумент команды (`git commit -m '…'`, `--note "…"`);
- тело heredoc с кавычками в разделителе (`<<'EOF'`, `<<"EOF"`, `<<\EOF`) и текст heredoc без кавычек вне подстановок;
- аргументы печатающих и читающих команд: `echo`, `printf`, `cat`, `grep`, `rg`, `sed`, `head`, `tail`, `jq`, `ls`, `diff`, `wc`;
- комментарии и текст, который есть только в других полях payload (например, `tool_input.description`).

Heredoc начинается только с оператора `<<` вне кавычек (`'…'`, `"…"`, `$'…'`), `${…}`, арифметики и комментариев, то есть на верхнем уровне и внутри `$(…)`, `(…)` и обратных кавычек. Текст `<<EOF` в кавычках, в аргументе другой команды или в комментарии не делает следующие строки телом heredoc и не скрывает merge на них. `<<<` — here-string, а не heredoc: следующие строки остаются командами. Тело и сам оператор исключаются из разбора команд, поэтому идиома `git commit -m "$(cat <<'EOF' … EOF)"` с апострофом в теле разбирается верно.

Неоднозначности решаются в сторону блокировки (fail closed):
- несколько отдельных некавыченных слов `gh pr merge` в аргументах неизвестной программы блокируются: такая программа может оказаться обёрткой;
- фрагмент, который по токенам не решить (незакрытая кавычка или подстановка, код `python -c`/`perl -e`/`node -e`, оболочка, читающая команды из stdin: `… | bash`, `bash <<< …`, вложенность глубже 8 уровней), проверяется регулярным выражением и может только добавить блокировку;
- оператор heredoc, который не разобрать (разделитель с `$` или частичными кавычками, сдвиг `<<` в арифметике или индексе массива, `case` внутри подстановки, перевод строки в кавычках или конец подстановки до тела), и незакрытая кавычка или подстановка: тогда тем же выражением проверяется весь текст команды вместе с телами heredoc;
- payload, который не разбирается как JSON или не содержит строковой `tool_input.command`, проверяется тем же выражением по сырому тексту;
- отсутствие Python или любая ошибка разбора дают код `2`.

Payload без слов `merge` и `accept` пропускается сразу, без запуска Python.

Не покрыто (как и прежней текстовой проверкой): содержимое файлов-скриптов (`bash x.sh`, `make`), программный текст других утилит (`awk`, команда `e` у `sed`), alias и функции оболочки, `gh alias`, косвенность через переменные (`$CMD`), merge через REST (`gh api`, `glab api`) и обфускация (`mer''ge`, `$'\x..'`, перенос `\` внутри слова).
## 3. Контракты
- **Вход (Input/Brief):** JSON-payload вызова инструмента Bash через стандартный ввод (`stdin`); решение принимается только по полю `tool_input.command`.
- **Выход (Output/Report):**
  - **Успех (Разрешение):** Код возврата `0` (пустой вывод), если команда не выполняет merge PR/MR.
  - **Отказ (Блокировка):** Код возврата `2` и текстовое сообщение в `stderr` с объяснением причины запрета, если команда выполняет merge, если её нельзя проверить или если Python не найден.
