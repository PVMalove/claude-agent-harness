## 1. Название и локализация
- **Английское название:** mark-qa-gate-passed
- **Русский перевод / Суть:**

```text
Маркировка успешного прохождения QA-гейта
```
## 2. Полное описание
Скрипт `mark-qa-gate-passed.sh` является хуком, который срабатывает после успешного выполнения команды инструмента Bash (`PostToolUse(Bash)`). Его основная задача — зафиксировать тот факт, что текущее состояние рабочего дерева (worktree) успешно прошло все проверки качества (QA-гейт).

Хук анализирует входные данные и проверяет, является ли только что выполненная команда последней в списке `qa_gate_commands` (определенном в файле конфигурации `.harness/project.json`). В linked worktree, где gitignored-каталог `.harness/` отсутствует, конфигурация берётся из корня проекта (`CLAUDE_PROJECT_DIR`), а если сессия сама запущена в linked worktree — из основного worktree репозитория; если её нет нигде, хук ничего не делает. Поскольку выполнение QA-гейта прерывается при первой ошибке, успешное завершение последней команды гарантирует, что все предыдущие проверки также были пройдены.

Совпадением считается только прогон всей последней команды. Её simple commands должны идти подряд с теми же разделителями, либо оболочка (`bash`, `sh`, `zsh`, `dash`, `ksh`, `powershell`, `pwsh`) должна получить её целиком строкой команды — `bash -lc '<команда>'` или `-Command '<команда>'`, как её запускает навык `qa-gate`. Перед командой не может стоять `||`, после неё допускаются только `&&`, и она не может быть запущена в фоне: иначе успех вызова Bash не означает её успех (`<команда> || true`, `<команда>; true`, `<команда> | tail`). Маркер не ставится и в двух других случаях. Первый — команда лишь содержит текст QA-команды, например более узкий выбор тестов `<команда> test_one`. Второй — команда выходит за подмножество bash, которое разбирает строгий лексер hooks: подстановка `$(...)`, присваивание перед программой `FOO=1 <команда>`.

В случае совпадения скрипт формирует уникальный идентификатор состояния репозитория, состоящий из хеша текущего коммита (`HEAD`) и хеша незакоммиченных изменений (`git diff`). Эта строка сохраняется в маркерный файл `.claude/.qa-gate/passed`. В дальнейшем наличие этого актуального маркера проверяется хуком `require-qa-gate.sh` перед созданием Pull Request'а.

Данный хук выступает в роли запасного механизма (fallback): обычно навык (skill) `qa-gate` самостоятельно записывает этот маркер через скрипт `record-qa-gate-pass.sh`, так как запускается в изолированном контексте. Этот хук покрывает случаи, когда команды QA-гейта выполняются агентом напрямую через вызовы Bash в основной сессии.
## 3. Контракты
- **Вход (Input/Brief):** JSON с параметрами выполненного действия (передается через `stdin`), содержащий информацию о запущенной Bash-команде.
- **Выход (Output/Report):** В случае успешной проверки создается или обновляется файл-маркер `.claude/.qa-gate/passed`, содержащий строку с текущим состоянием репозитория в формате `<HEAD_hash>:<diff_hash>`. Код возврата 0.
