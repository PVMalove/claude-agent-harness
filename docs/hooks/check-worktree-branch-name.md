## 1. Название и локализация
- **Английское название:** PreToolUse: Check Worktree Branch Name
- **Русский перевод / Суть:**

```text
Валидация имени ветки (worktree) перед ее созданием на соответствие конвенциям проекта и наличие задачи в трекере.
```
## 2. Полное описание
Хук `check-worktree-branch-name.sh` срабатывает перед выполнением инструмента `EnterWorktree` (событие PreToolUse). Он предназначен для обеспечения строгого соблюдения подхода "Issue First" и единого стиля именования веток в проекте.

Логика работы:
1. Из стандартного ввода (stdin) читается JSON-аргумент вызова инструмента и извлекается поле `"name"`.
2. Если имя явно не задано (например, происходит вход в существующий worktree по пути), проверки пропускаются.
3. Если имя задано, оно проверяется на соответствие регулярному выражению `branch_pattern` из `.harness/project.json` (по умолчанию `^feature/issue-[0-9]+-.+`). Если имя не соответствует шаблону, выполнение блокируется.
4. В случае успешной проверки шаблона из имени ветки извлекается номер issue (первая последовательность цифр).
5. Номер передаётся в `tracker-issue.py` — ту же проверку, что у `check-branch-name.sh`: трекер и проект определяет резолвер трекера проекта (поле `tracker` или `origin`), а `gh`/`glab` получают явный `-R`. Для локального трекера, неизвестного пути проекта, без пакета `.harness/health` или без установленного CLI проверка пропускается; без Python хук блокирует создание, как и `check-branch-name.sh`.
6. Если issue не найдена, issues в проекте отключены, CLI не авторизован или проект недоступен, хук прерывает выполнение инструмента и называет эту причину.
## 3. Контракты
- **Вход (Input/Brief):** JSON с аргументами вызова инструмента `EnterWorktree`, поступающий на `stdin`. Ожидается опциональное поле `"name"`.
- **Выход (Output/Report):** В случае успеха или отсутствия имени возвращается код возврата `0`. В случае нарушения конвенции именования или если issue не удалось подтвердить (не найдена, issues отключены, нет авторизации, проект недоступен, CLI не ответил или завершился с нераспознанной ошибкой) возвращается код `2`, а в `stderr` выводится сообщение с причиной.
