# CONTEXT.md

Глоссарий доменных терминов claude-agent-harness — инструмента, который разворачивает набор скиллов и правил для кодинг-агентов (Claude Code и др.) внутрь произвольного проекта.

## Язык

**Харнесс проекта** (project harness):
Набор файлов, установленных `harness init` в целевой репозиторий: `AGENTS.md`/`CLAUDE.md`, скиллы в `.harness/skills/`, ссылки обнаружения и lock-файл. Существует независимо от этого инструмента после установки — целевой проект не обязан иметь доступ к claude-agent-harness, чтобы харнессом пользоваться.
_Avoid_: инсталляция, харнесс (без уточнения «проекта» — путается с самим инструментом claude-agent-harness)

**Сидируемые файлы** (seed files):
Файлы, которые `harness` копирует в целевой проект только если они там отсутствуют (`AGENTS.md`, `.claude/agents/*`, хуки и т.д.). После первоначальной установки проект становится их полноправным владельцем. Они не отслеживаются в `harness.lock` и `harness update` по умолчанию их не перезаписывает (предотвращая затирание локальных правок).
_Avoid_: шаблонные артефакты, foundation-файлы


**Капабилити** (capability):
Именованный набор скиллов, выбираемый при `harness init --capability <имя>`. Описывается записью в `harness/CAPABILITIES.json`. Одна капабилити разворачивается за раз на одно имя скилла — если объединение выбранных капабилити даёт два разных исходника с одинаковым именем директории, `harness init` падает с ошибкой (`duplicate skill name`).
_Avoid_: пакет, набор скиллов (слишком общее)

**Vendor-скилл**:
Скилл, чьё содержимое — байт-в-байт снимок апстрима (`skills/vendor/mattpocock/...`), закреплённый через `third_party/mattpocock-skills/UPSTREAM.lock` на конкретный коммит. Правило репозитория: vendor-файлы никогда не редактируются вручную.
_Avoid_: ванильный скилл, оригинальный скилл

**First-party-скилл**:
Скилл, который поддерживается в самом claude-agent-harness (`skills/first-party/...`), а не унаследован от апстрима. Либо полностью новый (не существует в vendor — например `qa-gate`, `pr-composer`), либо полная замена одноимённого vendor-скилла для целей персонализации.
_Avoid_: кастомный скилл (используй термин только для first-party-скиллов, которые переопределяют одноимённый vendor-скилл — см. «Переопределение капабилити»)

**Переопределение капабилити** (capability override):
Механизм, которым капабилити расширяет другую капабилити (`extends`) и подменяет часть её скиллов на first-party-версии (`overrides`), добавляя сверху новые (`additions`) — без дублирования списка неизменённых скиллов. `pvmalove-suite` расширяет `mattpocock-suite`: 17 имён разрешаются в vendor как обычно, 8 имён переопределены в `skills/first-party/pvmalove/`: `to-spec`, `to-tickets`, `implement`, `ask-matt`, `code-review`, `grilling`, `triage`, `wayfinder`; доп. скиллы: `qa-gate`, `to-guide`, `setup-labels`. Итоговый разрешённый список — то, что реально попадает в snapshot и хешируется в lock; никакого пост-обработочного патчинга файлов после записи snapshot нет.
_Avoid_: патч, патчинг (речь не про diff/patch-файлы — те были рассмотрены и отклонены, см. ADR 0002 — а про подмену исходного пути скилла на этапе разрешения капабилити)

**Дрейф** (drift):
Состояние, в котором содержимое файлов на диске целевого проекта расходится с тем, что зафиксировано в lock-файле как ожидаемое. `harness health` считает любой дрейф проблемой (`unhealthy`), `harness update` без `--force` отказывается перезаписывать файлы с дрейфом.
_Avoid_: рассинхронизация, устаревание

**Проектный конфиг** (`.harness/project.json`):
Единственное место, откуда first-party-скиллы `qa-gate` и `pr-composer` (и хуки `check-branch-name`/`check-worktree-branch-name`) берут специфичные для проекта значения: команды lint/test/typecheck, PR-шаблон, `branch_pattern` (regex формата веток) и `language` (`ru`/`en` — язык вывода code-review и PR-шаблона). Заполняется интерактивно при `harness init`, если выбрана `pvmalove-suite`. Форма зафиксирована в `harness/project/project.schema.json` (деплоится рядом как `.harness/project.schema.json` — `$schema`-ссылка в самом файле даёт автодополнение в редакторе) и проверяется вручную в `harness health` (без стороннего `jsonschema`-пакета — в репозитории нет сторонних Python-зависимостей вообще). Не путать с харнесс-lock (`.harness/harness.lock`) — тот описывает *состояние установки скиллов*, а не *настройки проекта*.
_Avoid_: конфигурация проекта (слишком общее), settings

**Реестр скиллов проекта** (`.harness/skills/REGISTRY.md`):
Компактная таблица имя/путь/описание по каждому скиллу под `.harness/skills` — и харнесс-управляемому, и project-owned. Пишется автоматически при `init`/`adopt`/`update`/`lock-project-skills`, либо вручную через `harness registry`. Существует ради рантаймов без нативного project-скилл-рута (сейчас — Hermes Agent): `AGENTS.md` отправляет такой рантайм искать по этой таблице вместо сканирования `.harness/skills` напрямую. `harness health` считает его дырявым (`unhealthy`), если таблица отсутствует или расходится с тем, что реально лежит на диске.
_Avoid_: каталог скиллов (используй для `skills/REGISTRY.md` — каталога исходников этого репозитория; это другой файл на другом уровне)

**Provenance-лок проекта** (`.harness/overlays/project-local.lock`):
Файл с sha256-хэшами скиллов, которыми целевой проект владеет напрямую под `.harness/skills`, но которые не пришли ни из одной выбранной капабилити — например, скилл, добавленный владельцем проекта вручную. Пишется командой `harness lock-project-skills`, хэширует только git-видимые файлы (`git ls-files --cached --others --exclude-standard`), так что gitignore'нутые рантайм-артефакты (`node_modules`, кэши сборки) в лок не попадают и не создают ложный дрейф. `harness health` требует, чтобы каждый project-owned скилл был подтверждён в таком локе — иначе `project skills missing provenance lock`.
_Avoid_: overlay-лок без уточнения «проекта» (в апстриме overlay-лок — более общая схема, рассчитанная и на сторонние/скачанные наборы скиллов; этот репозиторий пока пишет только project-local-вариант)

**Инвентарь интеграций** (`.harness/integrations.json`):
Список нативных для рантайма файлов (`.mcp.json`, `.claude/settings.json` и т.п.), которыми пользуется проект: относительный путь, sha256, целевые рантаймы, текстовое verify-действие и имена секретных env-переменных — никогда сами секреты. `harness health` требует запись здесь для каждого такого файла, который реально есть на диске. Хэш доказывает целостность файла, не то, что интеграция подключена и работает — это подтверждается только в свежей рантайм-сессии.
_Avoid_: конфигурация интеграций (путается с проектным конфигом), секреты (в файле нет значений секретов, только имена переменных)
