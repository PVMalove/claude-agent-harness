# Changelog

Изменения выпусков записываются в формате [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) и версионируются по SemVer.

## [Unreleased]

### Added

- **[Миграция ledger по generations]:** `ledger migrate` создаёт проверенную generation с каноническими значениями `systemFields.v1`, а исходная generation и её история не меняются. Старые результаты проверок `passed`, `not-run` и `not_run_architect_read_only` сопоставляются явными правилами без нечёткой нормализации, а batch с неизвестным значением или нечитаемой записью уходит в quarantine, и действия по нему запрещены. Прерванную миграцию завершает следующий запуск, а повторный запуск ничего не меняет (#696).
- **[Просмотр и экспорт ledger]:** `ledger inspect [--batch]` и `ledger export --batch` показывают и выгружают batch из quarantine или с нечитаемыми записями, не блокируя ledger и ничего не записывая (#696).
- **[Совместимость рантаймов с systemFields.v1]:** назначение рантайма объявляет версию полем `system_fields_contract`, внешний adapter — глаголом `contract`, проектный extension — атрибутом `system_fields_contract`, а worker может подтвердить её флагом `dispatch self-report --system-fields-contract`. `dispatch preflight`, `dispatch create`, `dispatch send`, `qa run` и `report submit` до запуска и принятия возвращают структурированный отказ `runtime-compatibility` с evidence; несовместимый отчёт сохраняется только как непринятое evidence (#684).
- **[Удержание batch вместо abandon]:** неизвестные, отсутствующие, нечитаемые или несовместимые данные удерживают batch в runtime state store и поднимают attention `operational-hold`. Decision packet, `route_preview` и auto policy в таком случае не предлагают abandon, успех или маршрут по умолчанию. После устранения причины человек разрешает attention командой `batch attention resolve`, затем `recovery resume` снимает удержание (#684).
- **[Команды recovery]:** `recovery status`, `recovery reload` и `recovery resume --batch` работают без TTY и без Textual, печатают документ `recoveryStatus.v1` и завершаются кодом 0 или 2. `resume` сверяет store, ledger, brief, снимок harness runtime, snapshot конфигурации, Context Package открытых brief с base и candidate, совместимость, liveness, attention и approval, снимает удержание и не повторяет подтверждённые шаги. Общий API `recovery_api` даёт консоли действия fix, reload, resume, skip и abort с durable intent (#684).

### Changed

- **[Остановка auto policy без abandon]:** отказанный маршрут retry останавливает auto policy с `missing-evidence`, а не с `abandon-dead-end`; `abandon-dead-end` остаётся только для batch в `blocked` или `failed` по решению человека (#684).
- **[Ответ ledger migrate]:** `ledger migrate` требует Git checkout. В ответе появились поля `schema_upgraded` и `system_fields`, а `migrated` равно `true`, если изменилась схема ledger или значения полей (#696).
- **[Строгое чтение batch]:** чтение ledger останавливается, если batch, статус его dispatch или бриф изменены в обход ledger или откатились к ранней записанной версии, даже когда `state` остался прежним. Остановка называет версии записи и ведёт к `ledger inspect` и `ledger export`; допустимая история ранних версий по-прежнему читается (#727).

### Fixed

- **[Настройки консоли без project.json]:** Черновик настроек проекта без `.harness/project.json` снова строится из шаблона: консоль заполняет добавленный в 1.5.0 плейсхолдер `{{TEST_FIELDS}}` пустым значением, как `harness init` без флагов тестов, и шаблон больше не даёт некорректный JSON.
- **[Повтор publish и qa run]:** `dispatch publish` и `qa run` завершают прерванную запись до чтения batch, поэтому повтор команды после сбоя доходит до результата (#727).

### Breaking Changes

- **[Обязательное объявление systemFields.v1]:** внешний adapter должен отвечать на глагол `<adapter> contract [args] --repo <repo> --brief <brief>` строкой `{"system_fields_contract": "systemFields.v1"}`, а проектный extension — объявлять атрибут `system_fields_contract`. Extension без атрибута отклоняется в `dispatch preflight`, `dispatch create`, `dispatch send` и `qa run`, adapter без глагола `contract` — в `dispatch send`. Отказ `runtime-compatibility` не запускает worker; в `dispatch send` и `qa run` он ещё и удерживает batch до `recovery resume` (#684).

## [1.5.1] - 2026-10-18

### Added

- **[Профили проверок batch]:** Необязательный ключ `verification_profiles` в `.harness/orchestration.json` задаёт команды developer и code-review для области путей. `batch create` замораживает команды первого профиля, чьи `paths` покрывают все `--allowed-path`; при частичном покрытии или без ключа batch получает общие списки, а clean-room QA по-прежнему выполняет `verification_commands` (#756).
- **[Быстрые проверки developer-retry]:** Необязательный ключ `retry_verification` (`lint` и `test_command`) даёт повторной попытке developer команды lint и одну команду тестов по `related_tests` её Context Package. Без связанных тестов или без ключа повтор выполняет обычные команды developer; первый developer-dispatch, code-review и QA не меняются, а `checks_run` по-прежнему сверяется с brief дословно (#757).
- **[Состояние lock ledger]:** Когда ledger занят, `ledger lock-status` сразу отвечает, кто держит lock, сколько он уже держится и когда его можно будет снять, не дожидаясь освобождения ledger. Та же сводка видна в разделе оркестрации консоли и обновляется на живом экране (#759).
- **[Принудительное снятие lock]:** `ledger release-lock --force --approved-by --approved-at --reason` снимает lock при любом вердикте только по одобрению человека и пишет запись аудита с контрольной суммой, которую проверяет `ledger validate`. Ни одна политика, включая `auto`, команду не запускает; в консоли она доступна с подтверждением (#759).

### Changed

- **[Параллельный pytest]:** `make verify` запускает pytest до восьми воркеров вместо четырёх, если хватает ядер (#758).
- **[Windows-проверки CI]:** Задание `verify-windows` отключено и сохранено в `verify.yml` закомментированным, `windows-latest` убран из матрицы пробы векторной памяти; Linux-проверки не изменились (#753).

### Fixed

- **[Lock воркера из sandbox]:** Lock записывает PID-пространство и загрузку владельца, поэтому `ledger release-lock` больше не принимает чужой процесс с тем же pid за живого владельца: lock остановленного воркера из sandbox снимается по таймауту. Записи старого формата проверяются, как раньше (#759).
- **[Очистка после squash-merge]:** Шаг очистки `/to-pull-requests` проверяет влитость ветки по состоянию PR, а не по `git branch -d`, который после squash-merge всегда отказывает. Удаление локальной ветки агент предлагает разработчику, а `git branch -D` выполняет разработчик (#753).
- **[Проверка метаданных в PR интеграционной ветки]:** CI больше не проверяет сообщения коммитов, которые уже есть в default branch. Раньше PR, вливающий свежий `master` в интеграционную ветку, падал на чужом опубликованном коммите, а исправить его сообщение уже нельзя. Новые коммиты PR проверяются, как раньше (#753).
- **[Конфигурация консоли без `project.json`]:** Раздел конфигурации консоли снова строит документ `project.json` по умолчанию. С 1.5.0 шаблон содержит плейсхолдер полей тестов, консоль его не заполняла и отказывала с ошибкой «требуется корректный JSON» (#753).

## [1.5.0] - 2026-10-17

### Added

- **[Тест-автор в fast-implement]:** `/fast-implement` согласует с разработчиком seam до первого теста и при `{"status":"ok"}` от `test-author-preflight.sh` ведёт тот же цикл Red→Green→Refactor, что и developer полного маршрута: передача требования и сценария без алгоритма, проверка ожидания, скелет, запрет ослаблять принятое ожидание, лимит из трёх неудачных вызовов. Недоступный автор, упавший hook или недоступная изоляция сохраняют обычный `/tdd` с названной причиной; шаги coordinator, architect и QA не добавлены, ledger и approvals не изменились. Руководство `docs/agents/test-author.md` проекта описывает opt-in, настройки защищённого окружения, поддерживаемые версии и окружения и откат. Clean-room проверяет полный и короткий маршруты, новый и старый проект без `test_paths`, откат при упавшем hook и недоступной изоляции, простой тест и сценарии сборки и БД скриптованной заглушкой модели; реальный Claude Code подтверждает только `make test-author-probe`, качество тестов, написанных моделью, не измеряется (#557).
- **[Защищённая сборка и БД]:** Необязательные `test_runner.build` и `test_runner.database` готовят свежие артефакты и отдельную тестовую БД внутри песочницы. Сборка пишет только в пустые одобренные каталоги через временные backing-каталоги, тест читает артефакты без права записи; исходники и конфигурация остаются защищены. БД запускается только для выбранных SQL-тестов и завершается вместе с ними. Схема, CLI-флаги, `harness health` и preflight поддерживают настройки без изменения проектов, где они отсутствуют. Clean-room проверяет настоящий компилятор и PostgreSQL, включая rollback и ограничения; `HARNESS_REQUIRE_TEST_DATABASE=1` запрещает пропуск доказательства БД (#556).

- **[Тест-автор]:** Установка `pvmalove-suite` добавляет необязательный субагент `test-author`, его scoped guard `.claude/hooks/test-author-guard.py` и проверку активации `.claude/hooks/test-author-preflight.sh`. Субагент пишет один поведенческий тест и запускает его через `run-test.sh`: запись разрешена только внутри `test_paths` (зоны вида `<каталог>/**`), `Bash` только для вызова runner, а отказ возвращается мягким JSON с кодом 0 и не затрагивает dispatch и ledger. Preflight включает автора только при валидных `test_paths` и `test_runner`, подтверждённой изоляции, исправном guard и принятом в Claude Code доверии к проекту (`hasTrustDialogAccepted` для точного пути). Иначе он отвечает одной причиной (`project_untrusted`, `isolation_unavailable` и другие), а developer продолжает обычный маршрут. Поддержка ограничена Claude Code. Clean-room проверяет активацию, три состояния отсутствия доверия, мягкие отказы и настоящий поведенческий Red; `make test-author-probe` дополнительно запускает реальный Claude Code, который подтверждает срабатывание scoped hook и сам проходит цикл Red (#554). `make verify` и CI эту пробу не запускают: она требует учётных данных и тратит квоту.
- **[Изолированный запуск теста]:** Установка `pvmalove-suite` добавляет `.claude/hooks/run-test.sh <test-id>`: runner запускает один выбранный тест в песочнице bubblewrap, где production-код, `.git` и конфигурация runner доступны тесту и его дочерним процессам только на чтение, сокеты сервисов хоста в `/run` скрыты, а запись разрешена только в каталоги `test_paths`, временный каталог, кеш и отчёты запуска. Команда теста задаётся новым полем `test_runner` в `.harness/project.json`, а `test_paths` теперь описан в схеме и проверяется `harness health`. Новый проект получает оба поля флагами `harness init --test-path` и `--test-runner-command`; без флагов поля не пишутся. Без подтверждённой изоляции runner отказывает с понятной причиной и не запускает тест, а результат возвращает одной короткой JSON-строкой без вывода теста (#553).
- **[Цикл Red→Green→Refactor с тест-автором]:** Пока `test-author-preflight.sh` возвращает `ok`, developer ведёт каждый шаг реализации циклом с тест-автором: передаёт требование, seam, публичные сигнатуры и fixtures, проверяет ожидание по требованию до реализации и не ослабляет принятое ожидание ради Green. Статусы `red`, `needs_skeleton` и `contract_gap` обрабатываются явно; ошибки компиляции, импорта, fixture и окружения не считаются Red, а сразу зелёный тест не засчитывается. После трёх подряд неудачных вызовов по одному тесту действует обычный blocker, новых dispatch и состояний ledger нет. Clean-room сценарий со скриптованной моделью-заглушкой проверяет цикл (#555).
- **[Внешние runtime-адаптеры]:** Claude Code и Codex запускают отдельный worker в назначенном checkout по параметрам брифа. CLI устанавливает и обновляет адаптеры вместе с `backend-orchestration`, а настройки консоли показывают их состояние и требуют просмотра с подтверждением. Локальные файлы защищены от неявной замены; общий seed добавляет шесть разрешений для наблюдения за оркестрацией (#715).

- **[Запуск Claude worker в issue-worktree]:** Установка `backend-orchestration` добавляет `.harness/adapters/claude_worker.py` — runtime adapter для `transport: external`. Инструмент Agent не умеет стартовать subagent в существующем checkout (subagent стартует в основном checkout, `EnterWorktree` его там отклоняет), поэтому Claude in-process worker не может стартовать в `worker_worktree`. `dispatch send --adapter` запускает адаптер в `worker_worktree`, а он стартует отделённый headless `claude -p` на модели, effort и `allowed_tools` из брифа с `dontAsk`. Адаптер лежит вне хешируемого runtime-пакета, поэтому его установка не меняет пин открытого batch. Skill `implement` и руководство `worktrees.md` описывают оба пути: адаптер даёт настоящий cwd, а in-process subagent работает по абсолютным путям и `git -C`, и его self-report доказывает checkout, в котором он работает, а не cwd (#718).

### Fixed

- **[Восстановление незавершённой разработки]:** `batch rewind --preserved-commit` сохраняет явно подтверждённые коммиты и перечисленные через `--preserved-file` незакоммиченные файлы остановленного writer без отчёта или checkpoint. Следующий запуск проверяет сохранённый checkout; история, ручные согласования и бюджеты повторов сохраняются (#733).
- **[Кандидат после rewind]:** История и проверка ledger используют `source_dispatch_id` регистрации кандидата, поэтому повторный rewind после регистрации сохраняет читаемый ledger (#715).

## [1.4.6] - 2026-10-14

### Fixed

- **[База повторного batch]:** Batch, созданный на ветке с коммитами более раннего batch того же тикета, считает свои изменения от `branch_start_commit`, а не от `integration_base_commit`. Отчёты developer и publish, `scope_warnings`, checkpoint и оценка риска больше не включают чужие коммиты в `changed_files`, `commit_map` и `review_scope`. `risk assess --base-commit` принимает эту базу; замещающий batch и бриф считают, как раньше (#686).
- **[Context Package]:** Крупный Python-файл среди стартовых входит в пакет индексом символов с диапазонами строк, а не целиком. Если пакет не помещается в лимит токенов, самые тяжёлые стартовые файлы заменяются индексом вместо отказа `dispatch create` и `dispatch propose` (#687).

## [1.4.5] - 2026-10-13

### Added

- **[Стадии в отчётах консоли]:** Раздел «Отчёты» показывает все записанные стадии, в том числе без отчёта, а не только завершённые отчёты. Стадия без отчёта открывает хронологию batch, а список обновляется клавишей `r` или кнопкой ↻ (#676).
- **[Фильтры и порядок стадий]:** Стадии отбираются по статусу и по завершённости (все, незавершённые, завершённые) вместе с прежними фильтрами по тикету, роли, результату и дате. Порядок задаётся по времени, тикету, роли или статусу в обе стороны, а стадии с неизвестным временем остаются в конце (#676).
- **[Время до PR]:** Список и хронология batch показывают начало работы и время до создания PR, которое консоль при входе и по обновлению читает через `gh` или `glab` без записи в ledger. Если запрос не удался, значение остаётся «неизвестно», а при отсутствии PR консоль пишет «PR ещё не создан» (#676).
- **[Оценка запуска в dispatch status]:** `dispatch status` показывает для каждого dispatch оценку `startup`: состояние worker (`absent`, `reported`, `rejected-at-startup`, `stopped`, `live` или `unknown`), классификацию сбоя и то, что осталось неизвестным. Capacity, rate-limit и service-unavailable различаются между собой и отделены от дефектов кода (#679).
- **[Проверка флагов adapter]:** `dispatch send` сверяет `--adapter-arg` с `dispatch --help` adapter и отклоняет неподдерживаемый флаг до передачи brief, оставляя dispatch одобренным и неотправленным. Если справка не отвечает, причина попадает в `adapter_preflight` как ограничение, а не как подтверждение возможностей (#679).
- **[Проба runtime без worker]:** `dispatch runtime-probe` проверяет app-server runtime по brief: модель в `model/list`, поля `thread/start` и один `turn/start` на read-only thread без инструментов. Ошибка capacity, rate-limit или недоступности после `thread/start` даёт классифицированный сбой, а не READY; проба ничего не пишет в ledger и не заменяет model self-report (#679).

### Fixed

- **[Рекомендация для списка в настройке]:** Принятая рекомендация для поля-списка обновляет галочки выбора, а последующие правки сохраняются; частичный выбор больше не искажает JSON черновика (#676).
- **[Преждевременный abandon]:** Предупреждение о молчащем dispatch и сообщения о восстановлении называют read-only команды `batch auto-report`, `batch decision-packet`, `dispatch status` и `ledger validate` и предлагают ожидание, `resume-stop` или `rewind`, а `batch abandon` остаётся отдельным решением человека. Исчерпанный бюджет инфраструктурных повторов оставляет batch в состоянии остановки до выбора человека, счётчики не сбрасываются (#679).
- **[Перезапуск неизвестного worker]:** `batch resume-stop` отказывает, если `dispatch status` показывает worker в состоянии `live` или `unknown`, пока оператор не остановит worker через runtime и не повторит команду с `--runtime-stopped`. Прежний путь для отклонённого self-report, отчёта и сбоя запуска не меняется (#679).

## [1.4.4] - 2026-10-12

### Fixed

- **[Статусы отчёта]:** `blockers` и `risks` отделяют системный статус `none | present` от описания, включая обе оси review, checkpoint и продолжение. Политики читают статус, а неверный отчёт отклоняется до записи с подсказкой по исправлению; повторная отправка сохраняет автоматическое принятие (#672, #674).

### Changed

- **[Машинные поля высокого риска]:** Отдельные enum задают результаты интеграционных проверок (`passed / failed`), причины и маршруты retry, состояния batch и dispatch. Значения проверяются на границах чтения и записи; неизвестные литералы не становятся доказательством успеха или новым состоянием. Правила переходов, согласования, привязки к SHA и расхода retry-бюджета сохранены (#674).

### Breaking Changes

- **[Строгие enum отчёта]:** `blockers` и `risks` требуют объект `{"status": "none", "details": ""}` либо `{"status": "present", "details": "описание"}`, а результат проверки — ровно `pass`, `fail` или `not_run`. Старые строки, `passed`, `not-run` и `not_run_architect_read_only` больше не принимаются; сохранённые отчёты не переписываются (#672, #674).

## [1.4.2] - 2026-10-12

### Fixed

- **[Результаты проверок отчёта]:** `report submit` принимает равнозначные `pass` и `passed`, сохраняет успех как `pass`, а незапущенную проверку — как `not_run`. Явный `--worktree` проверяется в `dispatch preflight` и `dispatch send` (#662).

- **[Публикация dispatch]:** `dispatch publish` ограничивает время `git push` и точно сверяет ветку на remote. Зависший push больше не держит блокировку ledger.
- **[Освобождение очереди QA]:** Прерванный `qa run` освобождает lease и очередь QA. Захват очереди запуском `integration local-qa` больше не ломает восстановление dispatch.
- **[Checkpoint после сдвига базы]:** Координатор сравнивает checkpoint разработчика с базой отчёта после сдвига integration-ветки. Файлы из upstream больше не вызывают ложный отказ.
- **[Разрешение конфликтов]:** `integration resolve` после гонки с target называет созданный batch и точную команду `batch abandon`. Повтор resolve после этого проходит.
- **[Проверка локального QA]:** `integration local-qa` правильно сообщает, что ветка не основана на target. `context-package register` сравнивает `--base-commit` с фактической базой пакета.
- **[Файлы не в UTF-8]:** Координатор читает diff с файлами в устаревших кодировках без аварийного завершения. Отчёт или манифест роли не в UTF-8 даёт ошибку с инструкцией.
- **[Context Package]:** Context Package включает изменённые файлы с не-ASCII именами и вложенные ADR. Сбой Git при сборке пакета даёт ошибку с инструкцией.
- **[Устойчивость Repo Map]:** Repo Map переходит в деградированный режим при повреждённом lock, политике не в UTF-8 и ошибке чтения bundle. Кэш больше не оставляет временные файлы.
- **[Память проекта]:** Память принимает glob-шаблоны в корне проекта. Занятый индекс даёт ошибку «memory writer busy».
- **[Инвентарь интеграций]:** Установщик больше не перезаписывает нечитаемый `.harness/integrations.json`. Команда просит исправить файл и сохраняет записи проекта.
- **[Статистика доставки]:** Отчёт статистики проверяет карточку тарифов и сообщает инструкцию при нечитаемых файлах. Повреждённые записи ledger больше не прерывают отчёт.
- **[Пульт harness console]:** Экраны пульта показывают ошибку фонового запуска вместо бесконечного статуса «выполняется…». Дашборд по умолчанию перехватывает вывод команд.
- **[Сводка qa-gate]:** Сводка `qa-gate` сообщает `Status: ERROR`, если команду нельзя запустить. `diff_coverage` учитывает изменённые файлы с не-ASCII именами.

### Security

- **[Push из issue-ветки]:** Хук `block-direct-master` блокирует `git push --all`, `--branches`, `--mirror` и glob-refspec. Такие push могли обновить `main` или `integration/*`.
- **[Проверка приватных имён]:** `check_private_terms` блокирует публикацию, если Git не ответил вовремя. Раньше таймаут пропускал проверку.
- **[Каталог поколений ledger]:** Ledger отклоняет имя поколения с разделителями пути. Указатель больше не выходит за каталог ledger.
- **[Список vendor snapshot]:** Проверка vendor snapshot сверяет список файлов в `SHA256SUMS`, а не только их число. Лишняя или повторная строка больше не скрывает непроверенный файл.
