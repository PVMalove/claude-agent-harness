# Changelog

Изменения выпусков записываются в формате [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) и версионируются по SemVer.

## [Unreleased]

### Added

- **[Правила технического русского]:** Зафиксированы правила стандарта ASD-STE100 для документации и журнала изменений в `docs/technical-russian.md` (#645).
- **[Раздельная подготовка окружения QA]:** Параметр `qa_preparation` отделяет настройку окружения от выполнения проверок кода. Сбой инфраструктуры больше не списывает попытки разработчика (#618).
- **[Проверка прав доступа]:** Координатор проверяет права перед запуском QA, Git и публикации. При нехватке прав координатор останавливает операцию и выводит инструкцию по исправлению (#617).
- **[Классификация ошибок Git]:** Координатор точно определяет причину сбоя при операциях с Git. Система больше не подменяет отказ в доступе на ошибку конфликта слияния (#617).

### Changed

- **[Обновление контекстного пакета]:** Координатор автоматически создает новый контекстный пакет при изменении источников памяти. Команда `dispatch create` больше не падает с ошибкой устаревшего контекста (#636).
- **[Очистка ресурсов QA]:** Команда `qa run` корректно освобождает очередь и ресурсы при любых ошибках. Процесс не зависает и не блокирует следующие запуски (#617).
- **[Предупреждения о границах изменений]:** Выход за границы разрешенных путей теперь формирует предупреждение вместо жесткого отказа. Оператор подтверждает такое изменение явным действием `override-warning` (#633).

### Fixed

- `harness health --online`: `tracker.reachability` называет причину сбоя `git ls-remote origin` — нет учётных данных или они отклонены, ошибка TLS-сертификата, прокси или сеть — и даёт подсказку (credential helper или SSH-доступ, `http.sslCAInfo` для хоста, `HTTPS_PROXY`/`NO_PROXY`); иной сбой сохраняет прежнее сообщение и советует выполнить `git ls-remote origin` вручную. Stderr, URL `origin` и учётные данные в вывод не попадают.
- `harness install` больше не ставит `.harness/__init__.py`, поэтому `python -m unittest` без аргументов из корня проекта снова находит тесты проекта; `harness update` удаляет этот файл прежней установки. Точки входа установленного harness подключают его как пакет `harness` без корневого `__init__.py`, а закреплённый снимок рантайма не перекрывается пакетом `harness` из рабочего каталога.
- `harness memory sync` определяет трекер через резолвер трекера проекта (ADR 0011): поле `tracker` из `.harness/project.json` побеждает `origin`, путь проекта сохраняет подгруппы, GitLab-хост без `gitlab.` в имени с `type: gitlab` синхронизируется через `glab`. Хост адресуется явно: `gh api --hostname <host>` и `GITLAB_HOST=<host> glab api`.

## [1.3.0] - 2026-10-06

### Added

- **[Явная настройка трекера]:** Поле `tracker` в файле конфигурации задает тип и адрес трекера задач. Харнесс использует эти настройки для проверок, хуков и отчетов (#436).
- **[Проверка трекера в health]:** Команда `harness health` показывает параметры трекера в офлайн-режиме. При отсутствии настройки команда выводит готовый пример конфигурации (#436).
- **[Параметры трекера при установке]:** Команда `harness install` принимает параметры трекера через флаги командной строки. Установщик сохраняет существующий файл конфигурации проекта (#436).
- **[Полная поддержка GitLab]:** Скиллы и сценарии поддерживают работу с GitLab через CLI `glab`. Сценарии реализуют полный цикл запросов на слияние и адресацию хостов с нестандартным портом (#451).
- **[Статистика задач GitLab]:** Команда сбора статистики строит дерево эпика по связям задач. Метрики запросов на слияние собираются напрямую через `glab` (#449).
- **[Проверка версии glab]:** Команда `harness health` проверяет минимальную версию и авторизацию `glab`. При устаревшей версии команда предлагает инструкцию по обновлению (#451).
- **[Диагностика окружения в health]:** Команда `harness health` проверяет права песочниц и настройки кеша. Команда также контролирует соответствие базовых веток в открытых задачах (#583).
- **[Внутренний кеш uv]:** Харнесс размещает кеш пакетов внутри проекта (`UV_CACHE_DIR`). Это позволяет безопасно выполнять установку зависимостей в изолированной песочнице.
- **[Стандарт технического английского]:** Харнесс включает правила технического английского для общения агентов. Файл инструкций связывается с проектом без перезаписи существующих файлов (#521).
- **[Автоматическое согласование отчетов]:** Режим `approval_policy: auto` позволяет координатору автоматически принимать успешные промежуточные отчеты. Публикация и открытие PR по-прежнему требуют подтверждения человека (#455).
- **[Гибкий план коммитов]:** Координатор сверяет покрытие критериев готовности по плану архитектора. Несовпадение точного числа коммитов больше не останавливает конвейер (#501).
- **[Маршруты восстановления задач]:** Координатор классифицирует сбои инструментов по таблице маршрутов. Координатор перезапускает инструмент без списания попытки разработчика (#496).
- **[Перенос замечаний в ревью]:** Координатор переносит замечания в задание для проверки кода. Рецензент получает точный список пунктов для контроля (#501).
- **[Параллельное выполнение задач]:** Координатор запускает параллельные задачи в изолированных рабочих каталогах. Блокировки по общим зонам файлов сняты (#531).
- **[Регистрация проверок интеграции]:** Команда `integration prepare` связывает задачу с опубликованной веткой. Команда сохраняет неизменяемую запись проверок (#532).
- **[Автоматическое обновление ветки]:** Команда `integration refresh` обновляет ветку задачи при сдвиге целевой ветки. Разработчику не нужно переделывать работу вручную (#533).
- **[Разрешение конфликтов интеграции]:** Роль `conflict-resolver` разрешает конфликты слияния в рамках выделенного бюджета. Оператор принимает решение о продолжении сессии (#534, #537).
- **[Учет результатов CI]:** Команда `integration collect-ci` запрашивает статус внешних проверок из трекера. Успешный CI заменяет повторный запуск тяжелых локальных тестов (#535).
- **[Локальная проверка интеграции]:** Команда `integration local-qa` выполняет полный локальный контроль качества. Команда использует этот режим при отсутствии внешнего CI (#536).
- **[Навигация по шагам интеграции]:** Команда `integration next` подсказывает следующее необходимое действие. Команда `/to-pull-requests` автоматизирует подготовку ветки к слиянию (#537).
- **[Защита от утечки имен]:** Хуки и тесты блокируют публикацию приватных внутренних терминов. Проверка работает локально и в CI перед созданием коммитов.

### Changed

- **[Явная адресация в CLI]:** Команды `gh` и `glab` явно указывают целевой проект. Разработчики исключили ошибки перенаправления команд в чужой репозиторий.
- **[Права групп GitLab]:** Проверка доступа корректно обрабатывает права, унаследованные от родительских групп. Пользователи получают доступ без лишних настроек.
- **[Понятные ошибки проверки веток]:** Хуки проверки имен веток выводят точную причину отказа. Разработчик сразу видит проблему с доступом или номером задачи.
- **[Уточнение руководств проекта]:** Документация описывает только реально устанавливаемые проверки. Разработчики удалили недостоверные обещания проверок на стороне CI.
- **[Обоснованные блокировки задач]:** Скилл `/to-tickets` блокирует задачи только при реальной зависимости по данным. Пересечение файлов больше не создает ложных блокеров (#538).

### Fixed

- **[Точный разбор команд GitLab]:** Хук проверки распознает команды создания MR с короткими флагами. Разработчики устранили ложные срабатывания на текст внутри комментариев и кавычек.
- **[Проверка метаданных публикации]:** Хук проверяет параметры команд трекера и файлы описаний. Текст многострочных блоков ввода больше не анализируется как код.
- **[Создание интеграционной ветки]:** Хук защиты от прямых коммитов проверяет каждый каталог в команде. Публикация новой интеграционной ветки больше не блокируется.
- **[Блокировка только реальных команд]:** Хук опасных команд Git реагирует исключительно на реальный запуск. Харнесс разрешает упоминание команд в цитатах и скриптах.
- **[Корректная проверка путей]:** Хуки временных файлов разрешают запись в каталоги памяти агентов. Хуки проверяют объем вывода тестов только при реальном запуске.
- **[Фиксация проверок в worktree]:** Скилл `qa-gate` корректно находит конфигурацию в связанных рабочих каталогах. Скилл надежно записывает маркер прохождения тестов.
- **[Строгая фиксация контроля качества]:** Скрипт проверки выставляет маркер только при полном прохождении проверок. Маскировка ошибок через `|| true` больше не позволяет обойти контроль.
- **[Безопасное обновление эпиков]:** Скилл `/to-tickets` обновляет описание эпика через файлы. Это предотвращает искажение текста из-за экранирования в командной строке.
- **[Очистка неактивных рабочих каталогов]:** Команда жесткой очистки удаляет неактивные рабочие каталоги после отправки изменений. Мусор больше не накапливается на диске.
- **[Стабильная работа на Windows]:** Установщик корректно обрабатывает неинтерактивный ввод на Windows. Команда `health` экранирует пути и безопасно запрашивает задачи.
- **[Устойчивость блокировок журнала]:** Координатор повторяет попытки при занятой блокировке журнала. Координатор автоматически снимает поврежденные блокировки по таймауту.
- **[Надежный перезапуск разработчика]:** Повторный запуск разработчика наследует контекстный пакет и инструкции. Отмененные задачи не мешают продолжению работы.
- **[Устранение взаимных блокировок]:** Промежуточная фиксация изменений продолжается без задержек. Разработчики устранили ошибки зависания при проверке окружения (#606).
- **[Ранние отчеты остановки]:** Координатор корректно принимает отчет об остановке до изменения файлов. Конвейер требует соблюдения всех проверок перед кодированием (#607).

## [1.2.0] - 2026-10-02

### Added

- **[Локальная память проекта]:** Харнесс создает полнотекстовый поисковый индекс по локальным документам и решениям. Агенты находят прошлый опыт решения аналогичных задач.
- **[Команды управления памятью]:** Команды `harness memory` строят, пересобирают и тестируют индекс поиска. Поддерживается синхронизация снимков задач из трекера.
- **[Безопасный контекст задачи]:** Координатор отбирает релевантные карточки памяти по критериям готовности. Внешний недоверенный текст отсекается, а объем укладывается в бюджет токенов.
- **[Отчет об использовании памяти]:** Итоговый отчет исполнителя фиксирует использованные документы и выводы. Разработчик видит, какие решения помогли при реализации.
- **[Проверка памяти в health]:** Команда `harness health` проверяет доступность поиска, политику памяти и свежесть индекса. Пользователь получает предупреждение при устаревании данных.
- **[Общий индекс для worktree]:** Связанные рабочие каталоги читают поисковый индекс основного репозитория. Повторная индексация не тратит время и ресурсы.
- **[Контроль качества поиска]:** Офлайн-тесты измеряют точность поиска и уровень шума на типовых запросах. Это гарантирует релевантность выдачи контекста агентам.
- **[Руководство по памяти проекта]:** Документация подробно описывает настройку и обновление поисковой памяти. Руководство доступно в каталоге документации харнесса.

### Changed

- **[Настройки политики памяти]:** Конфигурация проекта поддерживает разделы `memory` и `memory_policy`. По умолчанию память выключена для сохранения обратной совместимости.

### Fixed

- **[Стабильность тестов консоли]:** Тесты консольного интерфейса завершаются без зависания асинхронных задач. Улучшена диагностика при проверках на Windows.

## [1.1.1] - 2026-10-02

### Fixed

- **[Возобновление работы разработчика]:** Повторный запуск разработчика продолжает цепочку коммитов кандидата. Конвейер не заходит в тупик при отклонении отчета.
- **[Ранняя проверка заданий]:** Команда `dispatch create` заранее проверяет корректность задания. Заведомо невалидные задания отклоняются с понятной подсказкой.

## [1.1.0] - 2026-09-28

### Added

- **[Чистое удаление харнесса]:** Команда `harness uninstall` полностью удаляет файлы харнесса из проекта. Команда создает резервную копию и требует явного подтверждения оператора.
- **[Удаление через консоль]:** Консольный интерфейс поддерживает безопасный план и выполнение удаления харнесса. Для запуска требуется ручной ввод слова-подтверждения.

## [1.0.1] - 2026-09-28

### Added

- **[Новые команды в консоли]:** Консоль поддерживает принудительное обновление файлов и предпросмотр очистки. Команды сгруппированы в удобном порядке.

### Changed

- **[Обновление интерфейса консоли]:** Интерфейс консоли получил контрастные рамки и заголовки панелей. Активные элементы списков и кнопок выделяются цветом.
- **[Улучшение панели Dashboard]:** Панель отображает ошибки и предупреждения с удобной прокруткой. Факты карты репозитория выводятся построчно.
- **[Повторный запуск проверок]:** Кнопка «Offline checks» в консоли перезапускает офлайн-проверки по запросу.

### Fixed

- **[Адаптивная верстка консоли]:** Панели консоли корректно прокручиваются в окнах небольшого размера. Элементы больше не накладываются друг на друга.

## [1.0.0] - 2026-09-28

### Added

- **[Первый стабильный выпуск]:** Выпущен переносимый Agent Harness с профилями возможностей, установщиком, оркестрацией и картой репозитория.
- **[Автоматическая публикация релиза]:** Релизы публикуются на GitHub с архивом и контрольными суммами. Публикация происходит автоматически при слиянии в основную ветку.
- **[Шаблон конфигурации оркестрации]:** Добавлен управляемый пример конфигурации распределенной оркестрации. Установщик создает рабочий файл конфигурации на основе этого примера.
- **[Справочник по оркестрации]:** Создана подробная документация по устройству координатора. Описаны все параметры конфигурации и их значения по умолчанию.
- **[Полный каталог скиллов]:** Файл `README.md` содержит структурированный список всех скиллов на русском языке. Добавлены руководства по командам проверки и консоли.
- **[Русские описания агентов]:** Каталог документации содержит переводы манифестов и описания проектных ролей на русском языке.
- **[Интерактивная консоль управления]:** Консольный интерфейс получил цветовую тему, справочный раздел и цветовую индикацию статусов диагностики.
- **[Разделы консоли харнесса]:** Консоль отображает статус установки, статистику конвейера и историю задач с фильтрацией по состояниям.
- **[Обновление руководства харнесса]:** Руководство дополнено навигацией по типовым задачам, шпаргалками по командам и восемью архитектурными диаграммами.
- **[Верификация архитектурных диаграмм]:** Все диаграммы проекта проходят автоматическую валидацию. Превью диаграмм включены в поставку документации.

### Changed

- **[Переименование глобального установщика]:** Скрипт установки глобального слоя переименован в `bin/install-global.py`.
- **[Централизация руководств харнесса]:** Документация харнесса перенесена в управляемый снимок `.harness/docs/`. Файлы обновляются автоматически командой `harness update`.
