# Diagnostics: соответствие терминальному макету

Источник: `docs/design/console-mockups/diagnostics.html`. Экран использует общую
оболочку из #741: меню, хлебные крошки, контекст, SectionCard, Fold, JumpLink и footer.
Порядок: заголовок и ручные команды → сводка и действия → CLI → карточки проблем →
фильтры и группы. Фильтры меняют список групп, общие счётчики остаются фактами отчёта.

Обоснованные отличия от HTML:

- Версия, ветка, путь, группы и числа берутся из приложения и Report. Данные HTML
  демонстрационные; время «только что» не показывается, поскольку Report не содержит времени.
- Все реальные группы сохраняются в порядке отчёта, включая hooks/directories и
  неизвестные токены. Первая группа не обязательно «Файлы харнесса».
- Карточки показывают ошибки и предупреждения. В раскрытых группах доступен полный
  список; в исходном свёрнутом состоянии проблемы видны один раз.
- Высота области карточек ограничена, внутри неё есть прокрутка. В 80×24 это
  оставляет сводку, действия и первую группу в начальном viewport даже с длинными
  сообщениями. Весь текст и команды остаются доступны прокруткой, без сокращения данных.
- В узком режиме CLI и пояснение ручных команд скрыты ради высоты. Они доступны
  после расширения терминала и в экспорте. Остальные группы собраны в Fold.
- Вместо нарисованной подсказки `y` используется фокусируемая кнопка копирования
  существующей команды. Переходы ведут по общей таблице check_route и ничего не запускают.
- Отсутствующие рекомендации/команды отмечаются явно. Онлайн-режим сообщает только
  о режиме запуска; успешная проверка трекера не обещается без реального результата.
- Сообщения ядра, IDs, fix.text, fix.command и fixes_applied не переводятся и
  отображаются буквально, включая Rich-подобную разметку. Переводятся только UI-строки.

Генерируемые SVG и логи находятся в `artifacts/`, не включаются в Git и должны
быть сохранены координатором до очистки worktree. Исторические логи предыдущих
попыток не удаляются и не являются результатами текущих проверок.
